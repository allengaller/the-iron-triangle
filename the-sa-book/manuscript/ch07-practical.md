# 第 7+ 章　方案设计实战：可运营性一票否决

> 方案不是画图。是把未来运营的成本画进图里。本章三个动作：多方案权衡、可运营性一票否决、架构图叙事。核心是那道硬门槛：**方案上线后运营不起来，一票否决**。评审接口对接交付与 TAM（铁三角见[《The TAM Book》附录 V](../../the-tam-book/manuscript/appx-v-tam-bte-sa-triangle.md)）。承诺纪律接[第 9 章](ch09-commitment-engineering.md)四问。

## 7+.1 前置条件与目标

| 前置条件 | 检查内容 | 缺项处理 |
| --- | --- | --- |
| 需求已定稿 | 需求五要素齐全（口径引 TAM 书附录 C） | 先补需求调研 |
| 约束已知 | 预算、工期、合规约束白纸黑字 | 先要约束清单 |
| 评审接口 | 交付与 TAM 侧评审人已指定 | 先定评审人 |
| 模板 | 权衡记录模板可用 | 先建模板 |

完成标志有三项：至少两案带代价、可运营性过评审。一张图讲清价值。

| 目标 | 完成标志 | 主要证据 |
| --- | --- | --- |
| 两案带代价 | 推荐案与备选案各有三张牌 | 权衡记录 |
| 运营可过 | 五维检查全过或否决处置留痕 | 评审签认单 |
| 一图讲清 | 三层图经非技术听众验证 | 架构图 |

## 7+.2 操作一：多方案权衡（带代价）

### 操作步骤

1. 至少出两案。推荐案与备选案，或激进案与稳健案。
2. 每案亮三张牌：成本、风险、运营负担。缺一张牌不算方案。
3. 写权衡记录（ADR，架构决策记录，Architecture Decision Record）。三段：选择理由、放弃理由、翻盘条件。
4. 给客户选择题。带各自代价，让客户拍板。

### 权衡记录三段

| 段 | 回答的问题 |
| --- | --- |
| 选择理由 | 为什么是它 |
| 放弃理由 | 另一案输在哪 |
| 翻盘条件 | 出现什么信号就换案 |

### 预期结果

客户拿到的是选择题。每个选择都能追到权衡记录。

### 常见错误

- 只出一案。名为建议，实为绑架。
- 三张牌只亮成本。运营负担藏起来。
- 权衡记录写成事后辩护。

## 7+.3 操作二：可运营性一票否决

### 五维检查

方案上线后，客户的运维团队与我方交付、TAM 要转得起来。五个维度逐项过：

| 维度 | 判定问题 | 判据来源 |
| --- | --- | --- |
| 可运维 | 监控、告警、值班接得住吗 | 值班标准见[《The TAM Book》附录 I](../../the-tam-book/manuscript/appx-i-on-duty-standard.md) |
| 可变更 | 升级与回退路径走得通吗 | 变更治理见[流程 P12](../../the-tam-book/manuscript/appx-b-tam-process-system.md) |
| 可交接 | 文档与知识转移完备吗 | 移交三件套见[模板 19](../../the-tam-book/templates/19-commitment-handover-kit.md) |
| 可持续 | 人力与技能配比够吗。客户团队会用吗 | 客户侧培训与认证 |
| 可退出 | 迁移与替换路径存在吗 | 退出成本可算，避免锁死 |

### 一票否决项（命中即停）

- 无回退方案，或回退没验证过；
- 无监控无告警，或告警没人接收；
- 没有人会运维，也没有培训计划；
- 退出成本算不清。

### 否决处置

1. 先改方案。能补的补上。
2. 补不上的，写进风险清单。让客户书面知情。
3. 客户坚持要，风险清单随合同签认。责任落纸面。
4. 不悄悄放行。放行的是知情决定，不是疏忽。

### 操作步骤

1. 方案成稿前自查五维。
2. 送交付与 TAM 侧评审。逐维签认。
3. 命中否决项，改方案或走否决处置。
4. 评审签认单入方案基线。

### 预期结果

五维全过，或否决处置留痕。方案基线里有评审签认单。

### 常见错误

- 评审走过场。签认单事后补。
- 把否决项写进风险清单就算完。客户不知情。
- 运营负担推给“售后再优化”。

## 7+.4 操作三：架构图叙事（一张图讲清价值）

### 三层图

| 层 | 内容 | 听众 |
| --- | --- | --- |
| 业务层 | 业务价值与旅程 | 业务决策者 |
| 逻辑层 | 组件、接口与数据流 | 技术评审 |
| 部署层 | 资源、容量与成本 | 预算把关 |

### 操作步骤

1. 先画业务层。价值先行，技术后置。
2. 逻辑层只画与承诺有关的组件。无关组件不上图。
3. 部署层带容量与成本量级。用信封背面估算。
4. 讲图顺序：业务层 → 逻辑层 → 部署层。
5. 图的承诺纪律：图上每个框都要能过[第 9 章](ch09-commitment-engineering.md)四问。

### 预期结果

非技术听众能复述方案价值。图上每个框都能过四问。

### 常见错误

- 一图塞满组件。听众找不到重点。
- 讲图从技术讲起。业务听众先睡着。
- 图上有框，四问答不上。

## 7+.5 验收标准

| 验收项 | 通过标准 | 验证方式 |
| --- | --- | --- |
| 多案权衡 | 至少两案带三张牌 | 核对权衡记录 |
| 翻盘条件 | 每案写明换案信号 | 核对权衡记录 |
| 五维检查 | 全过或否决处置留痕 | 核对评审签认单 |
| 否决处置 | 客户书面知情 | 核对风险清单 |
| 三层图 | 业务层先行、框框过四问 | 评审会上实测 |
| 非技术验证 | 业务听众能复述价值 | 会后抽问 |

关键项是五维检查、否决处置和三层图。任一关键项未通过，方案不得出评审。

## 7+.6 执行故障排查

| 症状 | 常见原因 | 处理动作 |
| --- | --- | --- |
| 客户抱怨没有选择 | 只出一案 | 补备选案带代价 |
| 交付拒收方案 | 五维没过 | 退回补检查 |
| 评审签认事后翻案 | 否决项事后才发现 | 入否决处置流程 |
| 风险清单引发争议 | 客户首次知情在签合同时 | 否决即告知，不攒到最后 |
| 讲图冷场 | 没从业务层开始 | 重排叙事顺序 |
| 换案扯皮 | 翻盘条件没写 | 补权衡记录三段 |

反复出现的问题进入复盘流程（[《The TAM Book》附录 R](../../the-tam-book/manuscript/appx-r-problem-retrospective-standard.md)）。

## 7+.7 执行检查清单

- [ ] 至少两案，每案带三张牌
- [ ] 权衡记录三段齐全（选择、放弃、翻盘）
- [ ] 五维检查逐项过，签认单入基线
- [ ] 否决项已处置，客户书面知情
- [ ] 三层图业务层先行
- [ ] 图上每个框都过四问
- [ ] 非技术听众验证过价值叙事

---

**本章要点回顾**

1. 方案是选择题。至少两案，三张牌，翻盘条件写清。
2. 可运营性是硬门槛。五维：可运维、可变更、可交接、可持续、可退出。命中否决项就停。
3. 否决不悄悄放行。改方案，或让客户书面知情。放行的是知情决定。
4. 一张图讲清价值：业务层先行，图上每个框都能过四问。
