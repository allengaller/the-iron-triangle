# 第 13 章　方案设计与评审

> 流程篇第三步。设计技能在[第 7+ 章](ch07-practical.md)。本章管流程执行：怎么排期、怎么过评审、怎么冻结。四个动作：设计排期、内部评审三关、方案基线冻结、下游移交。上游是[第 12 章](ch12-requirements-research.md)需求基线。下游是第 14 章竞争投标与第 15 章 POC。

## 13.1 前置条件与目标

| 前置条件 | 检查内容 | 缺项处理 |
| --- | --- | --- |
| 需求基线 | 三件齐、客户签认 | 回第 12 章 |
| 估算底稿 | 容量与成本量级已出 | 补第 5+ 章 |
| 评审人 | 三关评审人已定 | 先定评审人 |
| 模板 | SA-01、SA-03 可用 | 先补模板 |

完成标志有四项：排期有时间盒、三关有签认。基线有版本、移交有清单。

| 目标 | 完成标志 | 主要证据 |
| --- | --- | --- |
| 排期有时间盒 | 设计、评审、冻结排到日 | 设计排期 |
| 三关有签认 | 技术、运营、商务各签认 | 评审签认单 |
| 基线有版本 | 版本号冻结 | 方案基线 |
| 移交有清单 | 下游输入清单齐 | 移交清单 |

## 13.2 操作一：设计排期

### 操作步骤

1. 输入清单核对：需求基线三件、估算底稿、竞争位置（SA-04）。
2. 设计分工：主设一人（SA），评审人提前约档期。
3. 时间盒三段：设计、评审、冻结，各写到日期。
4. 排期发内部干系人确认。评审人档期没确认，排期是空的。

### 预期结果

输入齐。分工到人。三段时间盒确认。

### 常见错误

- 输入缺件开设计。返工从这里开始。
- 评审人临时约。档期对不上，评审缩水。
- 时间盒弹性。设计拖成无底洞。

## 13.3 操作二：内部评审三关

### 三关

| 关 | 审什么 | 判据来源 | 签认人 |
| --- | --- | --- | --- |
| 技术关 | 六维初筛、估算量级 | [第 5+ 章](ch05-practical.md) | 技术评审人 |
| 运营关 | 可运营性五维一票否决 | [第 7+ 章](ch07-practical.md) | 交付与 TAM |
| 商务关 | TCO 口径、报价底座 | [第 8+ 章](ch08-practical.md) | BTE |

### 操作步骤

1. 方案成稿先进技术关。量级错了打回重估。
2. 运营关五维逐项过。否决项走处置（7+ 章）。**一票否决不豁免**。
3. 商务关核 TCO 假设与报价三段。口径与 SA-03 一致。
4. 三关签认单入方案基线。缺签认不冻结。

### 预期结果

三关各签认。否决项处置留痕。签认单入基线。

### 常见错误

- 三关并一关开。评审会变成通气会。
- 运营关走过场。交付期翻车的账回到这里。
- 签认事后补。签认单成了橡皮章。

## 13.4 操作三：方案基线冻结

### 冻结规则

- **版本号**：方案版本语义化。冻结即锁版；
- **冻结内容**：方案正文、三层图、承诺清单、TCO 摘要、权衡记录；
- **变更走书面**：冻结后变更走变更记录。口头变更不认。

### 操作步骤

1. 三关过完才冻结。缺关不锁版。
2. 冻结清单逐项打钩。缺项写明补期。
3. 锁版入台账。方案版本可追溯。
4. 变更申请走书面流程。审批后新版本。

### 预期结果

版本可追溯。变更留痕。冻结清单零缺项。

### 常见错误

- 先冻结后补评审。锁版锁了个半成品。
- 变更口头。版本对不上账。
- 清单缺项不留痕。下游拿到缺口方案。

## 13.5 操作四：下游移交

### 移交清单

| 下游 | 输入 |
| --- | --- |
| 第 14 章 竞争投标 | 冻结方案、对比叙事（SA-04）、报价三段 |
| 第 15 章 POC | POC 目标（SA-02）、场景清单、成功标准 |
| 第 9 章 承诺管理 | 承诺清单（模板 19 四要素） |

### 操作步骤

1. 移交按下游清单逐项对。缺项不移交。
2. 移交会双方确认。交接记录留痕。
3. 上游缺口不带入下游。缺口回设计补。

### 预期结果

下游输入零缺。移交留痕。

### 常见错误

- 移交靠转发文件。清单不对，缺口进下游。
- 缺口顺流而下。投标现场才发现方案没定稿。

## 13.6 验收标准

| 验收项 | 通过标准 | 验证方式 |
| --- | --- | --- |
| 输入清单 | 三件齐、估算在 | 核对清单 |
| 设计排期 | 三段时间盒确认 | 核对排期 |
| 技术关 | 六维与量级过关 | 核对签认单 |
| 运营关 | 五维全过或处置留痕 | 核对签认单 |
| 商务关 | TCO 与报价口径一致 | 核对签认单 |
| 基线冻结 | 锁版、清单零缺项 | 核对基线台账 |
| 下游移交 | 逐项对、双方确认 | 核对移交记录 |

关键项是运营关签认、基线冻结和下游移交。任一关键项未通过，方案设计不得视为合格。

## 13.7 执行故障排查

| 症状 | 常见原因 | 处理动作 |
| --- | --- | --- |
| 方案返工 | 输入缺件开设计 | 补基线三件再启动 |
| 评审缩水 | 评审人没约档 | 提前锁档期 |
| 交付拒收 | 运营关走过场 | 重开关门评审 |
| 版本对不上账 | 变更口头 | 走书面变更记录 |
| 投标现场失守 | 移交有缺口 | 回上游补齐再移交 |
| 签认变橡皮章 | 事后补签 | 评审当刻签认 |

反复出现的问题进入复盘流程（[《The TAM Book》附录 R](../../the-tam-book/manuscript/appx-r-problem-retrospective-standard.md)）。

## 13.8 执行检查清单

- [ ] 需求基线三件与估算底稿齐
- [ ] 设计排期三段时间盒确认
- [ ] 技术关六维与量级签认
- [ ] 运营关五维签认，否决处置留痕
- [ ] 商务关 TCO 与报价签认
- [ ] 方案基线锁版，清单零缺项
- [ ] 冻结后变更有书面记录
- [ ] 下游移交逐项对、双方确认

---

**本章要点回顾**

1. 设计排期三件事：输入齐、分工到、时间盒锁。
2. 评审三关分开过。运营关一票否决不豁免，签认当刻做。
3. 基线先过关再冻结。变更走书面，版本可追溯。
4. 下游移交按清单对。缺口不顺流而下。
