# 第 6+ 章　需求调研实战

## 6+.2 操作一：干系人访谈

### 三类访谈提纲

| 对象 | 核心问题（示例） | 听什么 |
| --- | --- | --- |
| 业务口 | 现在最疼的是什么？指标卡在哪？ | 痛点与目标 |
| 技术口 | 现有架构哪里动不得？历史踩过什么坑？ | 约束与兼容 |
| 决策口 | 这次立项要解决什么？预算与时间边界？ | 风险与责任 |

### 操作步骤

1. 先列干系人清单。按业务、技术、决策三口分类。
2. 每口一轮访谈。单场 60 分钟内。
3. 提问用场景句：“上一次出问题是什么时候？”不用抽象句。
4. 当场复述确认。听懂的判据是对方点头。
5. 记录分两栏：事实与判断。不混写。

### 预期结果

三口各有访谈记录。事实与判断分栏。

### 常见错误

- 只约技术口。目标和预算全靠猜。
- 抽象提问：“您有什么需求？”对方答不出。
- 记录不分栏。事后分不清哪些是事实。

## 6+.3 操作二：场景还原

场景还原是一场 90 分钟的三方工作坊。业务、技术、SA 同场。

### 操作步骤

1. 画时间线。从触发到结果，还原一次完整业务场景。
2. 标痛点。时间线上的每个卡点。
3. 挖约束。每个卡点的技术与组织约束。
4. 量化卡点。影响多少笔、多少钱、多少人。
5. 双方确认时间线。签字的纪要才算数。

### 预期结果

时间线完整。卡点带量化。纪要双方确认。

### 常见错误

- 工作坊变宣讲会。SA 讲方案，客户听。
- 卡点不量化。方案优先级排不了。
- 纪要不确认。事后各说各话。

## 6+.4 操作三：痛点→方案反向翻译

### 反向翻译表

| 痛点 | 量化影响 | 方案要素 | 验证手段 |
| --- | --- | --- | --- |
| | | | |

### 操作步骤

1. 每个痛点一行。量化影响填不出的行退回场景还原。
2. 方案要素只写要点。展开进方案正文。
3. 验证手段对应五要素的验收标准（口径引[《The TAM Book》附录 C](../../the-tam-book/manuscript/appx-c-methodology-mapping.md)）。
4. 表合入 SA-01 第二节。逐行过一遍客户确认。

### 预期结果

痛点零遗漏。每行有量化与验证。客户逐行确认。

### 常见错误

- 痛点和方案对不上号。翻译链断裂。
- 验证手段写“上线后看效果”。没有测量方法。
- 只翻译显性痛点。冰山下层丢了。

## 6+.5 验收标准

| 验收项 | 通过标准 | 验证方式 |
| --- | --- | --- |
| 三口访谈 | 业务、技术、决策各一轮 | 核对访谈记录 |
| 记录分栏 | 事实与判断分开 | 抽查记录 |
| 场景还原 | 时间线签字纪要 | 核对纪要 |
| 卡点量化 | 每个卡点有数字 | 抽查还原表 |
| 反向翻译表 | 痛点、量化、要素、验证齐全 | 核对 SA-01 |
| 客户确认 | 逐行确认 | 核对签认 |

关键项是三口访谈、场景还原和反向翻译表。任一关键项未通过，需求调研不得视为合格。

## 6+.6 执行故障排查

| 症状 | 常见原因 | 处理动作 |
| --- | --- | --- |
| 需求反复变更 | 只访谈一个口 | 补齐三口访谈 |
| 痛点对不上方案 | 翻译链断裂 | 重走反向翻译表 |
| 量化填不出 | 场景还原没到位 | 重开还原工作坊 |
| 客户不认需求理解 | 没逐行确认 | 补签认环节 |
| 决策口失联 | 渠道没打通 | 请 BTE 补渠道 |
| 验证手段落空 | 写成“看效果” | 补测量方法与数据源 |

反复出现的问题进入复盘流程（[《The TAM Book》附录 R](../../the-tam-book/manuscript/appx-r-problem-retrospective-standard.md)）。

## 6+.7 执行检查清单

- [ ] 三口访谈各一轮，记录事实判断分栏
- [ ] 访谈用场景句，不用抽象句
- [ ] 场景还原时间线经双方签字
- [ ] 每个卡点有量化数字
- [ ] 反向翻译表四列齐全
- [ ] 验证手段有测量方法与数据源
- [ ] 客户逐行确认需求理解

---

**本章要点回顾**

1. 访谈三口都要约。场景句提问，事实判断分栏记。
2. 场景还原是三方工作坊。时间线要签字，卡点要量化。
3. 反向翻译表四列：痛点、量化、要素、验证。填不出量化的行退回还原。
4. 需求理解要客户逐行确认。确认过的理解才是方案的地基。
