# 第 8+ 章　证明计划实战

> 本章把第 8 章的证明设计落成七步操作：写主张、选类型、定标准、设环境、排角色、跑执行、出结论。配套 [BTE-04 证明计划](../templates/bte-04-proof-plan.md)。

## 8+.1 前置条件与目标

| 前置条件 | 检查内容 | 缺项处理 |
| --- | --- | --- |
| 客户决策问题 | 这次证明要支持什么决定 | 先问清用途 |
| 技术方案 | 证明对象与边界 | 先与 SA 对齐 |
| 客户场景 | 数据、流程、并发、权限 | 先做场景访谈 |
| 资源 | 环境、专家、时间 | 先定资源 |
| 验收人 | 客户谁签字，内部谁签字 | 先定签认人 |

完成标志有四项：主张唯一；标准可测；环境贴近生产；结论有签认。

| 目标 | 完成标志 | 主要证据 |
| --- | --- | --- |
| 主张清楚 | 一句话说清证明什么 | 证明计划第 1 节 |
| 标准量化 | 每条标准有阈值与取数方式 | 证明计划第 3 节 |
| 环境可信 | 数据、并发、权限接近生产 | 环境清单 |
| 结论可签 | 通过、带条件、不通过三选一 | 结论签认页 |

## 8+.2 操作一：写主张

### 步骤

1. 用一句话写：在什么场景下，证明什么能力，达到什么水平；
2. 主张只写一个，不写“同时证明五点”；
3. 主张要与客户的决策问题直接相关；
4. 主张要可证伪，不写“效果良好”；
5. 与客户确认这句话。

### 预期结果

客户与团队对“这次证明什么”有同一句话。

### 常见错误

- 主张太多，每个都浅；
- 主张与客户决策无关；
- 主张不可证伪，结论只能靠感觉。

## 8+.3 操作二：选证明类型

### 步骤

1. 判断客户最担心什么：有没有、行不行、比对手如何、别人用过吗；
2. 对应选 Demo、POC、Benchmark、参考客户；
3. 能用低成本证明的，不上一上来就做 POC；
4. 金融级或高风险场景，组合两种以上证明；
5. 写清每种证明的局限。

### 预期结果

证明类型与客户疑虑匹配，成本可控。

### 常见错误

- 所有单都做 POC，资源耗尽；
- 只做 Demo，客户仍不信；
- Benchmark 不写测试条件。

## 8+.4 操作三：定标准与退出条件

### 步骤

1. 每条标准写指标、阈值、取数方式、时间窗；
2. 标准分三档：通过、带条件通过、不通过；
3. 写退出条件：命中即停，不继续烧资源；
4. 标准与退出条件双方签字；
5. 标准事后不改，除非双方书面同意。

### 预期结果

证明开始前，双方知道什么算成，什么算败，什么时候停。

### 常见错误

- 标准事后解释；
- 只写通过标准，不写退出条件；
- 客户口头同意，没有书面。

## 8+.5 操作四：设计环境与数据

### 步骤

1. 列出环境要素：算力、网络、存储、权限、第三方依赖；
2. 数据由客户提供，脱敏后使用；
3. 数据量、并发、样本分布接近生产；
4. 写清环境与生产的差异，以及差异对结论的影响；
5. 环境就绪前不开执行。

### 预期结果

证明环境可信，结论可外推。

### 常见错误

- 用厂商标准环境，不用客户数据；
- 数据量太小，结论不成立；
- 环境差异不写，客户过度解读结论。

## 8+.6 操作五：定角色与时间表

### 步骤

1. 列角色：客户业务、客户技术、SA、交付、TAM、BTE；
2. 每个角色写职责与决策权；
3. 排时间表：环境就绪、执行、复盘、结论；
4. 设周会或日会，按证明周期定；
5. 关键节点写进商机里程碑。

### 预期结果

每个人知道什么时候做什么，谁签字。

### 常见错误

- 角色不清，出事互相推；
- 时间表没有缓冲；
- 证明与商机里程碑脱节。

## 8+.7 操作六：执行与记录

### 步骤

1. 按计划执行，不临时改场景；
2. 每次测试记录时间、输入、输出、异常；
3. 失败场景也要记录，不隐藏；
4. 每天同步进展，异常 24 小时内升级；
5. 关键数据双人复核。

### 预期结果

证明过程可追溯，结论有证据。

### 常见错误

- 只记录成功案例；
- 数据没有原始记录；
- 异常不升级，拖到结论才说。

## 8+.8 操作七：出结论与归档

### 步骤

1. 按事前标准出结论：通过、带条件通过、不通过；
2. 带条件通过的，写清条件、Owner、期限；
3. 结论双方签字，不口头默认；
4. 证据归档：数据、配置、记录、结论；
5. 结论进入承诺清单与方案基线。

### 预期结果

结论可签、可查、可移交。不达标也如实写。

### 常见错误

- 不达标也说达标；
- 结论没有签字；
- 证据不归档，交付期无法复现。

## 8+.9 验收标准

| 验收项 | 通过标准 | 验证方式 |
| --- | --- | --- |
| 主张唯一 | 一句话，可证伪 | 抽查证明计划 |
| 标准量化 | 每条有阈值与取数方式 | 核对标准表 |
| 退出明确 | 命中即停条件写清 | 核对退出条件 |
| 环境可信 | 数据与并发接近生产 | 核对环境清单 |
| 记录完整 | 成功与失败均有记录 | 抽查测试记录 |
| 结论签认 | 三选一，双方签字 | 核对结论页 |
| 证据归档 | 数据、配置、记录齐全 | 核对归档目录 |

关键项是标准量化、结论签认、证据归档。任一未过，证明不算合格。

## 8+.10 执行故障排查

| 症状 | 常见原因 | 处理动作 |
| --- | --- | --- |
| 证明做完客户仍不信 | 主张与决策无关 | 重写主张，对准决策问题 |
| 标准吵不清 | 事前没量化 | 停下来先定标准 |
| 环境搭不起来 | 资源没前置 | 先定环境 Owner 与日期 |
| 客户质疑结论 | 记录不全 | 补原始数据与测试记录 |
| POC 变成无底洞 | 没有退出条件 | 命中退出条件即停 |
| 客户不签字 | 结论模糊 | 改成三选一，写清条件 |

## 8+.11 执行检查清单

- [ ] 主张一句话，可证伪
- [ ] 证明类型与客户疑虑匹配
- [ ] 每条标准有指标、阈值、取数方式
- [ ] 退出条件写清，命中即停
- [ ] 环境与数据接近生产
- [ ] 角色、职责、时间表明确
- [ ] 成功与失败均有记录
- [ ] 结论三选一，双方签字
- [ ] 证据已归档并进入承诺清单

---

**本章要点回顾**

1. 七步：写主张、选类型、定标准、设环境、排角色、跑执行、出结论。
2. 主张只写一个，要能证伪，要对准客户的决策问题。
3. 标准事前定，分通过、带条件、不通过三档。
4. 退出条件命中即停，防止 POC 变成无底洞。
5. 环境与数据贴近生产，差异要写清。
6. 结论双方签字，证据归档，进入承诺清单。
