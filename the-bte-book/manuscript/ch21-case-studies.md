# 第 21 章　案例解剖（虚构化案例集）

> 本章四个案例全部虚构，用于演示判断与取舍，不对应任何真实客户。每个案例按五段展开：背景、冲突、BTE 动作、结果、复盘。读案例不读“成功”，读“当时还能怎么选”。案例体例与脱敏规定见[《The TAM Book》第 20 章](../../the-tam-book/manuscript/ch20-case-studies.md)与[附录 E](../../the-tam-book/manuscript/appx-e-contribution-guide.md)。

## 21.1 案例读法

四个案例对应四类典型难题：

| 案例 | 难题 | 主要能力 |
| --- | --- | --- |
| A 银行 | AI 项目按量计费，成本失控 | 商业结构 |
| B 保险 | 大单机会好，交付接不住 | 机会判断 |
| C 证券 | 技术领先，客户不信 | 证明设计 |
| D 支付 | 出海采购，合规卡住 | 采购与决策链 |

每个案例的结果都不是“完美胜利”。真实项目里，BTE 常常要在不完美中做取舍。

## 21.2 案例一：A 银行 AI 客服

**背景**：A 银行要上智能客服，目标是降低人工坐席压力。客户要求按 Token 计费，预算按年封顶。

**冲突**：按量计费听起来公平，但流量波动大。旺季成本翻倍，淡季收入不够覆盖固定成本。客户又不同意保底。

**BTE 动作**：

1. 算三档流量情景，给客户看成本曲线；
2. 提出“保底 60% + 超量阶梯 + 年度调价”结构；
3. 把保底对应客户最低业务量，客户能接受；
4. 加成本上限条款，超出部分双方分担；
5. 把模型版本变更写进合同，避免升级后成本失控。

**结果**：客户接受混合结构。第一年流量低于预期，保底覆盖固定成本；第二年流量上涨，超量收入覆盖增量成本。

**复盘**：纯消费模式把风险全留给厂商，纯保底把风险全留给客户。混合结构不是折中，是把风险放到最能控制的一方。

## 21.3 案例二：B 保险核心替换

**背景**：B 保险核心系统替换，预算大、周期长、监管要求高。客户希望一年内上线。

**冲突**：机会评分很高，但交付资源不足。按客户时间表，需要三个团队并行，公司只能抽出一个半。销售压力要求先签。

**BTE 动作**：

1. 用 BTE-01 重评，交付风险维度打低分；
2. 做 pre-mortem：假设项目已失败，列出五个原因；
3. 向客户提出分两期上线，第一期先换非核心模块；
4. 把“一年全量上线”改为“一年一期上线 + 第二年全量”；
5. 合同写明分期验收与资源前提。

**结果**：签约时间推迟两个月，但交付资源可保障。第一期上线后，客户信心上升，第二期扩展。

**复盘**：赢单质量比赢单速度重要。交付接不住的单，签得越快，亏得越快。

## 21.4 案例三：C 证券极速交易

**背景**：C 证券要建极速交易系统，对延迟极敏感。客户技术团队强，对厂商宣传不信任。

**冲突**：产品在标准 benchmark 上领先，但客户不信标准测试。客户要求在自己的机房、自己的行情、自己的策略下验证。

**BTE 动作**：

1. 不做“产品介绍”，先做证明设计；
2. 主张只写一条：在客户环境、客户行情下，95 分位延迟低于阈值；
3. 标准事前量化，客户技术团队签字；
4. 环境由客户提供，数据由客户给，厂商只带工具；
5. 结论三选一，不达标如实写。

**结果**：第一次测试未达标。BTE 没有美化，和 SA 一起定位到网络配置问题。第二次测试达标，客户认可证据。

**复盘**：技术可信不是“我们说行”，是“客户能验证”。第一次不达标反而增加信任，因为结论真实。

## 21.5 案例四：D 支付出海

**背景**：D 支付要进入一个新市场，需要本地合规与数据驻留。客户希望厂商承担全部合规责任。

**冲突**：商务上想签，但合规边界不清。厂商不能替客户承担当地监管责任，客户又不愿自己承担。

**BTE 动作**：

1. 拉法务与合规做边界表：谁负责牌照、谁负责数据、谁负责审计；
2. 把“全部合规”拆成可执行条款；
3. 引入本地伙伴承担部分落地责任；
4. 合同写明责任上限与退出机制；
5. 向客户高层讲清边界，不隐瞒。

**结果**：客户接受分责结构。项目延期三个月，但没有出现合规事故。

**复盘**：跨境项目里，最大的风险不是技术，是责任边界。BTE 不能把不可承担的责任写进合同。

## 21.6 跨案例规律

四条规律：

1. **结构先于价格**：A 案例证明，商业结构错了，价格再高也亏。
2. **交付先于赢单**：B 案例证明，交付接不住，赢单是负债。
3. **证据先于说服**：C 案例证明，客户不信形容词，信自己验证的结果。
4. **边界先于承诺**：D 案例证明，不可承担的责任，不能写进合同。

四条规律指向同一件事。**BTE 的价值在于设计可执行的交易。不在于把单签下来。**

## 21.7 误用边界

读案例要避免三种误用：

1. **照搬动作**：案例里的结构、标准、条款，都有具体条件。换客户、换行业、换监管，要重算。
2. **只看结果**：结果受运气、团队、客户配合影响。要看当时的判断依据，不看事后光环。
3. **把虚构当事实**：本章案例全部虚构，数字与机构均为演示，不可引用为行业证据。
