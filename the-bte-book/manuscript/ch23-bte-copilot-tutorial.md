# 第 23+ 章　BTE Copilot 搭建教程

> 本教程带你搭一个只服务自己的 BTE Copilot。目标不是“什么都能干”，是把客户研究、会议准备、材料初稿、竞争卡四件事跑顺。全程用沙箱资料，不碰真实客户数据。

## 0. 准备

### 0.1 你需要什么

- 一个经批准的 AI 工具账号；
- 一个本地文件夹，放脱敏资料；
- 四份样例：产品简介、两个脱敏案例、一份合同条款摘要；
- 30 分钟连续时间。

### 0.2 安全边界

- 不使用真实客户名、真实报价、真实合同；
- 不上传个人信息与敏感数据；
- 所有产出标“草稿”，人工复核后才可用。

### 0.3 完成标志

做完本教程，你会有：

1. 一个可检索的知识库；
2. 四套可复用提示词；
3. 一份客户简报样例；
4. 一份会议准备样例；
5. 一份材料初稿样例；
6. 一张竞争卡样例；
7. 一套抽检与上线检查规则。

## 1. 建工作区

1. 建四个文件夹：`knowledge/`、`prompts/`、`outputs/`、`reviews/`；
2. `knowledge/` 放产品、案例、条款、常见问题；
3. `prompts/` 放提示词版本；
4. `outputs/` 放 AI 产出；
5. `reviews/` 放复核记录。

**预期结果**：资料与产出分开，能追溯。

**常见错误**：所有文件堆在一个文件夹，找不到版本。

## 2. 整理知识库

1. 每份资料重命名为 `类型-主题-版本-日期`；
2. 删掉过期内容；
3. 每份资料开头写三行：来源、适用范围、不适用场景；
4. 按客户、行业、场景建三个索引；
5. 只放脱敏资料。

**预期结果**：提问时能找到依据，不靠模型记忆。

**常见错误**：资料不标版本，AI 引用过期内容。

## 3. 写第一套提示词：客户研究

提示词结构：

```text
角色：你是我的客户研究助理。
任务：根据我提供的公开资料，输出一页客户简报。
结构：业务、组织、技术、机会四块。
规则：
1. 每条信息标来源与日期；
2. 找不到来源的写“未核实”；
3. 不猜测，不补全；
4. 输出不超过 600 字。
```

1. 把提示词存到 `prompts/customer-research-v1.md`；
2. 用两份公开资料测试；
3. 检查是否每条有来源；
4. 删掉没有来源的内容；
5. 记录修改点。

**预期结果**：30 分钟内出一页可用简报。

**常见错误**：提示词不写“未核实”，模型会编。

## 4. 写第二套提示词：会议准备

提示词结构：

```text
角色：你是我的会议准备助理。
输入：客户简报、上次会议纪要、本次目标。
任务：输出会议准备表。
结构：
1. 本次要拿到的三个结果；
2. 按角色分组的六个问题；
3. 三个价值假设；
4. 三个风险问题；
5. 上次行动项。
规则：问题要具体，不问“有什么需求”。
```

1. 存到 `prompts/meeting-prep-v1.md`；
2. 用一份样例客户测试；
3. 检查问题是否适合对方角色；
4. 人工删掉不合适的问题；
5. 把最终版存到 `outputs/`。

**预期结果**：会前有目标、有问题、有行动项。

**常见错误**：问题太多，会上问不完。

## 5. 写第三套提示词：材料初稿

提示词结构：

```text
角色：你是我的方案材料助理。
输入：客户场景、需求五要素、方案边界、目标读者。
任务：先出提纲，我确认后再出初稿。
规则：
1. 不写产品没有的能力；
2. 每个数字标来源或“待核实”；
3. 不写“领先”“最佳”等形容词；
4. 初稿标“AI 草稿”。
```

1. 存到 `prompts/draft-v1.md`；
2. 先让 AI 出提纲；
3. 人工改提纲；
4. 再出初稿；
5. 技术事实交 SA 复核，商务事实自己复核。

**预期结果**：初稿省时间，事实可追溯。

**常见错误**：跳过提纲，直接出全文。

## 6. 写第四套提示词：竞争卡

提示词结构：

```text
角色：你是我的竞争情报助理。
输入：公开资料、客户需求。
任务：输出竞争卡。
结构：客户需求、我方位置、对手位置、证明、边界。
规则：
1. 事实行标来源；
2. 判断行标依据；
3. 承认对手优势；
4. 不写全优表。
```

1. 存到 `prompts/competitive-card-v1.md`；
2. 用公开资料测试；
3. 检查事实与判断是否分列；
4. 人工补充边界；
5. 每季度更新。

**预期结果**：竞争卡有事实、有边界、可更新。

**常见错误**：用模型编造对手信息。

## 7. 建提示词版本库

1. 每个提示词带版本号与日期；
2. 每次修改写三行：改了什么、为什么、效果如何；
3. 旧版本不删，标“停用”；
4. 每月回看一次；
5. 效果差的提示词停用。

**预期结果**：提示词可迭代，不越改越乱。

**常见错误**：提示词改完不记录，出了问题找不到原因。

## 8. 做月度抽检

1. 每月抽 10 份 AI 产出；
2. 检查四项：事实、来源、边界、口径；
3. 错误分三类：编造、过期、口径错；
4. 每类写一个改进动作；
5. 改进动作回写提示词或知识库。

**预期结果**：错误越来越少，产出越来越稳。

**常见错误**：只抽检不改进。

## 9. 真实数据上线检查

在把真实客户资料放进工具前，逐项确认：

- [ ] 工具已获公司批准；
- [ ] 数据已脱敏或获客户授权；
- [ ] 访问权限最小化；
- [ ] 日志可审计；
- [ ] 产出有人复核；
- [ ] 退出机制清楚；
- [ ] 客户知情（如合同要求）。

任一未过，不上真实数据。

## 10. 完成判定

你已完成本教程，如果：

1. 四套提示词可复用；
2. 客户简报 30 分钟内出；
3. 会议准备表可用；
4. 材料初稿有提纲与复核；
5. 竞争卡事实与判断分列；
6. 月度抽检有记录；
7. 真实数据上线检查全过。

---

**本章要点回顾**

1. Copilot 只服务自己，先跑顺四件事，不追求全能。
2. 知识库要标来源、版本、日期、边界。
3. 四套提示词：客户研究、会议准备、材料初稿、竞争卡。
4. 所有产出标“草稿”，人工复核后才可用。
5. 提示词要版本化，月度抽检要回写改进。
6. 真实数据上线前过七项检查，任一未过不上。
