# 第 6 章　客户与决策链洞察

> 技术再匹配，决策链不通，单也赢不了。BTE 要懂三件事：客户的业务怎么跑，谁真正拍板，预算什么时候有。本章讲业务语境、决策链三链、多线程与采购节奏。

## 6.1 为什么 BTE 要懂客户

BTE 的专业不是产品参数，是“把技术放进客户的业务与组织里”。

只懂技术，会犯三个错：

1. 把客户说的需求当成真需求；
2. 把友好接口人当成决策人；
3. 把技术评审通过当成采购通过。

懂客户，才能判断五件事。为什么现在做，谁受益，谁受损。钱从哪里出，谁能否决。

## 6.2 业务语境

业务语境有四层：

| 层 | 看什么 | 对 BTE 的用处 |
| --- | --- | --- |
| 商业模式 | 客户怎么赚钱，成本结构如何 | 判断价值假设是否成立 |
| 业务目标 | 增长、成本、风险、合规 | 把技术能力翻译成业务后果 |
| 业务日历 | 预算、结算、监管、峰值 | 判断采购与上线时机 |
| 竞争压力 | 同业在做什么，客户怕落后吗 | 判断紧迫性 |

金融客户还要多看一层：监管日历。年报、半年报、决算、监管报送、重保窗口，都会影响项目节奏。

业务日历不是背景知识，是销售节奏。客户在决算期不签新项目，在监管检查前不换核心系统。BTE 逆着日历推，事倍功半。

## 6.3 决策链三链

决策链不是一张组织图，是三张图。

### 6.3.1 决策链

谁拍板，谁签字，谁有否决权。

常见角色：

| 角色 | 关心什么 | 典型问题 |
| --- | --- | --- |
| 经济买家 | 投入产出、战略价值 | 这笔钱花得值吗 |
| 技术买家 | 架构、集成、可运维 | 技术上靠谱吗 |
| 用户买家 | 好用、省事、不添乱 | 上线后我怎么用 |
| 教练 | 内部信息、推动意愿 | 我怎么帮你赢 |
|  blocker | 风险、既有利益 | 为什么要换 |
| 采购 | 流程、比价、合规 | 价格与条款合适吗 |
| 法务 | 责任、数据、退出 | 合同风险可控吗 |
| 安全 | 数据、权限、供应链 | 会不会引入新风险 |

AI 项目还多三类角色：CAIO、数据治理、模型风险。他们不一定签字，但能否决。

### 6.3.2 影响链

谁影响谁，谁听谁的。

影响链常常不在组织图上。技术负责人的意见，可能受外部顾问影响；业务负责人的决定，可能受同业案例影响。

BTE 要找到三类影响源：内部专家、外部顾问、同业标杆。

### 6.3.3 防线

谁会把项目挡下来，为什么。

防线通常有四道：技术评审、安全评审、采购评审、法务评审。每道防线都有否决点。

BTE 的早期动作，是把防线前置。不要等到合同阶段才发现安全过不了。

## 6.4 决策链的五个属性

| 属性 | 问题 | 不合格信号 |
| --- | --- | --- |
| 权力 | 这个人能不能拍板 | 只见接口人，见不到决策人 |
| 态度 | 支持、中立、反对 | 不知道对方态度 |
| 触达 | 能不能约到、说上话 | 约三次约不到 |
| 覆盖 | 关键角色是否都覆盖 | 只覆盖技术口 |
| 冗余 | 每个关键角色有没有备份 | 支持者一走，线全断 |

五个属性里，冗余最容易漏看。单点依赖是商机最大的隐性风险。

## 6.5 多线程

多线程不是多认识几个人。多线程是三个维度同时成立：

**多线程 = 覆盖 × 深度 × 冗余**

- **覆盖**：业务、技术、采购、法务、安全，关键角色都有接口；
- **深度**：每个接口不是点赞之交，能交换真实信息；
- **冗余**：每个关键角色至少两条线，不依赖一个人。

多线程的动作：

1. 画三链图，标出空白；
2. 为每个关键角色设计一次“有价值”的接触，不空聊；
3. 每次接触带一个对方关心的问题或证据；
4. 记录态度变化，不记录“聊得不错”；
5. 支持者变动时，48 小时内补线。

## 6.6 预算与采购节奏

客户买不买，不只看需求，还看预算与流程。

常见采购阶段：

| 阶段 | 客户动作 | BTE 动作 |
| --- | --- | --- |
| 立项 | 写可研、算预算 | 提供价值案例与方案轮廓 |
| 预算 | 排优先级、砍项目 | 帮客户论证优先级 |
| 入围 | 筛供应商、定标准 | 影响标准，提供资质 |
| 招标 | 发标、评标 | 拆评分点，组织应答 |
| 评标 | 技术、商务、价格 | 答疑、澄清、守住承诺 |
| 合同 | 条款、审批 | 风险分配、法务协同 |
| 上线 | 交付、验收 | 交接、首批价值证据 |

BTE 要判断客户现在处在哪个阶段。阶段错位，动作就错。客户还在立项，你忙着报价；客户已经招标，你才开始做关系，都来不及。

## 6.7 信号与更新

决策链会变。BTE 要捕捉变化信号：

- 支持者离职、调岗、失势；
- 组织重组，汇报线变化；
- 预算削减或项目延期；
- 新监管要求，优先级变化；
- 竞争对手进场，POC 邀请；
- 采购流程变更，入围标准调整。

信号出现，更新三链图，重新评估机会。不要用三个月前的判断，做今天的决定。

## 6.8 边界与伦理

懂决策链，不等于操纵决策链。

三条红线：

1. **不误导**：不虚构案例、不夸大能力、不隐瞒风险。
2. **不贿赂**：不通过不正当利益影响决策。
3. **不绕过**：不绕过采购、法务、安全等必经流程。

关系经营是长期信任，不是短期技巧。靠信息差与手段赢的单，会在交付期还回来。

## 6.9 常见误区

### 误区一：认识人多就是决策链清楚

认识人多，不等于知道谁拍板。决策链看权力、态度、触达、覆盖、冗余，不看通讯录长度。

### 误区二：只搞技术口

技术口能说“行”，不能说“买”。业务、采购、法务、安全，任何一口都能卡住。

### 误区三：把支持者当决策人

支持者帮你，不代表他能拍板。要验证：他能不能调动预算，能不能影响最终签字人。

### 误区四：忽略采购与法务

技术赢了，合同输了，单还是丢。采购与法务要早进场，不要留到最后。

### 误区五：关系就是吃饭喝酒

关系是信任账户。吃饭能开户，不能存款。存款靠一次次兑现承诺。

### 误区六：决策链画一次就够

组织会变，预算会变，态度会变。三链图要随商机更新。
