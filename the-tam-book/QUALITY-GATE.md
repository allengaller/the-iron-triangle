# QUALITY-GATE.md — 内容门禁

> 这道门禁只回答两个问题：**稿子有没有薄到不能用？体裁有没有写错？**
> 它不回答"写得好不好"。那个问题只能靠人读。

## 一、为什么加这道门禁

本书已有三道形式门禁：长句、被动语态、链接与表格列数。三道全部可脚本化，也全部通过。但通读会发现内容仍偏薄：断言多、证据少、同构多。

原因不在某个章节，在生产流程：**能过审计的指标被当成了质量本身**。长句拆短、被动改主动、链接补齐——这些做完，稿子"合格"了，但读者仍然学不到东西。于是内容向"可分块、可登记、可校验"单向收敛。

这道门禁的立场是：不假装能量化可读性。它只测几个粗粒度代理指标，用来**定位哪里薄**，把判断权交回给人。

## 二、分级：block 与 warn

| 级别 | 含义 | 处置 |
|---|---|---|
| **block** | 体裁矛盾、结构破损 | 文件不算完成品，当期必修，`--strict` 退出码 1 |
| **warn** | 内容厚度不足 | 进整改台账，不阻断发布 |

判据一句话：**block 管"能不能用"，warn 管"写得好不好"。**

这条分界是本门禁最重要的设计。可读性没有阈值，用量化阈值去卡"写得好不好"，会重复本书犯过的错——作者开始为指标写作。

## 三、指标口径与盲区

每个指标都是代理指标。**盲区必须写在它旁边**，否则会被当成事实。

| 指标 | 定义 | 测不到什么 |
|---|---|---|
| 论证密度 | 含因果连接词（因为/所以/因此/意味着/前提/代价/权衡/反例…）的散文段与清单条目，占比 | 论证是否成立；说"因为"不等于说得对 |
| 具象密度 | 每千中文字中带单位的数据（%/天/小时/万元/QPS…）的出现次数 | 数据是否真实、是否来自本场景；数字可编 |
| 清单化率 | 列表行占非表格非标题正文行的比例 | 清单是否合理；How-to 本就该清单化 |
| 段落均长 | 散文段平均中文字数 | 段落是否连贯；把长段切碎同样能拉低 |
| 失效边界词 | 反例/失效/例外/前提是/除非/边界/代价/局限等的出现次数 | 是否真的承认了边界；堆词也能过 |
| 回顾占比 | "要点回顾"字数占全文比例 | 回顾是否有价值 |
| n-gram 重复 | 四字片段重复率 | 同义改写（换词复述测不出） |
| 表格密度 | 每千中文字表格行数 | 表格是否必要 |

## 四、骨架只查结构可供性

骨架检查只看三样东西，因为只有这三样既是项目明文约定、又不靠措辞就能核：

- Explanation：有"学习效果清单"（AGENTS.md 明文规则）
- How-to：有步骤类表述 + 至少 3 个 `- [ ]` 勾选项
- Reference：至少一张表
- Tutorial：分步 + 成果验证

**刻意不查**"有没有讲机制""有没有写误区"。这类判定只能靠关键词，而关键词可以被动词套利——把"机制"两个字塞进标题就能过。讲得好不好交给密度指标和人工通读。

## 五、Goodhart 防线（三条禁令）

门禁一旦成为交付条件，就会有人优化它。以下三条不是建议，是纪律。

1. **禁止为过线编造数据。** 某节确实没有量化对象（如岗位边界定义），就让它留在 warn，并在章内注明"本节无量化对象"。编一个数字，比留一条 warn 严重得多。
2. **禁止为过线改变排版形态。** 把清单拆成碎段凑段落均长、把段落并成清单凑清单化率，都是作弊。形态要服务内容，不能服务指标。
3. **调阈值必须重跑 `--calibrate` 并记入 HANDOFF。** 改阈值不改正文，等于改尺子而不是改身高。同一天内多人调阈值，视为异常。

**可疑信号**：某个指标突然全部达标，而文件字数几乎没变。这说明作者在与门禁对齐，而不是与读者对齐。

## 六、附录准入三问（防批量同构）

本书 43 个附录 > 36 个正文文件。同构审计给出了硬证据：**13 个“落地件”骨架完全相同，字数集中在 1,360–1,744（跨度 22%）**。

这不是抄袭（簇内文本重合中位数只有 0.04），是**同一个模板套了十三遍**。每份单独看都合格，合起来是同一张表的十三次填写。

新增附录前必须回答三问，答不上来不立项：

1. **能否并入现有附录的一节？** 附录数量已经超过正文，合并优先于新增。
2. **删掉它，哪条结论会站不住？** 答不上来说明它是装饰。
3. **跑 `similarity_audit.py` 看它落在哪个簇。** 进入 5 个以上成员的簇，一律不立项。

**自 2026-11-10 起，不再接受同构落地件。** 新增操作类内容优先并入对应主件的 howto，或补进既有落地件的既有小节。

同构审计的另一个发现：附录 P/Q（公共云/专有云服务质量标准）文本重合 0.18，属全书最高。两份本应“共用框架、差异在责任边界”，实际共用过多。下次改版应把共用部分抽到前言，两版只留差异。

## 七、工作流

| 时机 | 命令 |
|---|---|
| 写完一章 | `python3 scripts/content_gate.py --only chXX` |
| 交稿前 | `python3 scripts/content_gate.py --strict` |
| 生成台账 | `python3 scripts/content_gate.py --report` |
| 定阈值 | `python3 scripts/content_gate.py --calibrate` |

台账处理原则：**block 当期清零；warn 按"改它值不值"排序，不按数量排序。** 一个 6,000 字章节的具象密度 0.9 和一个 1,500 字附录的 2.4，前者优先。

## 八、它不测什么

以下五件事，任何指标都代替不了，只能靠人读：

- 论证是否成立（逻辑谬误、因果倒置）
- 事实是否准确（交给 `xref_check.py`、`standards/` 与人工核对）
- 案例是否可信（脱敏是否彻底、结果是否有外部锚点）
- 读者是否能读懂（需要真实试读）
- 是否像人写的（AI 文风不在本门禁范围）

门禁是筛子，不是标准。筛出来的必须人看，筛掉的也不必都改。

## 九、与既有脚本的分工

| 脚本 | 管什么 |
|---|---|
| `xref_check.py` | 路径、章号、附录字母、模板号、B 节号 |
| `xref_check2.py` | 节号级引用 |
| `scripts/content_gate.py` | 单文件的内容形态与厚度 |
| `scripts/similarity_audit.py` | 跨文件同构：骨架复刻与批量填充 |
| `scripts/gen_metadata.py` | 元数据：文件数、类型分布、字数、索引 |
| `scripts/claim_audit.py` | 数值断言的出处与标注 |

为什么要两个内容脚本：单文件 n-gram 只能发现“自己抄自己”，发现不了“十三份套同一模板”。跨文件同构才是批量生产的指纹。

## 九之二、元数据门禁（2026-11-10 加）

这一类问题与前八节不同。前八节管“稿子写得好不好”，这一节管“门面上的数字对不对”。

背景：评估发现 README 写“附录 30 个”，磁盘上是 43；写“合计 66 个正文文件”，实际 79；类型写“混合 12”，实际 0；模板写 22，实际 23。导读、GTM 落地页、类型总览各有一份不同的错数。

根因不是不认真，是结构性的：数字是手写的，分散在四处，任何一次增文件都会让它们同时失真。手改只能追上今天，追不上明天。

治法三层：

1. **能算的不写。** 文件数、类型分布、字数、模板数、标准库份数，全部由 `scripts/gen_metadata.py` 从磁盘算。
2. **算出来的锁住。** 文档里的数字包在 `<!-- META:key -->` 标记区里，标记区归脚本所有。
3. **不一致就拦。** `--check` 发现漂移返回退出码 1，与 `content_gate --strict` 同级。

索引也进入生成物之列。`manuscript/99-index.md` 由 `--index` 从磁盘重建，章节、模板、附录三层。改标题或增删文件后必须重跑，否则索引会变成另一份漂移源。

**可疑信号**：`--check` 一次就过，而这一轮明明加过文件。这说明要么文件没加进去，要么有人手改了标记区。两者都要查。

**盲区**：标记区只能锁住已标记的地方。新写一句“本书有 30 个附录”不会报错，因为脚本不知道那句话在陈述事实。防这条靠审阅，不靠脚本。写新句子时若出现可计算的数字，先加标记再填值。

## 九之三、数值断言出处（2026-11-10 加）

背景：评估第 10 项。全书大量数值断言零出处。资源水位“不超过 70%”、EOL 前“6–12 个月”、抽查“10%”、99.995% 对应“支付清算级”。这些可能是对的行业经验。但读者无从判断它是标准条款、厂商口径，还是作者手感。

在自称“标准”的语境下，这个缺口会被专业读者第一眼抓住。

治法不是给每个数字找出处。那不可能，也不诚实。治法是把数字分类，各类带各的标签。

| 标注 | 含义 | 怎么核 |
|---|---|---|
| 〔标准〕 | 国标、行标或监管规章条款 | 查原文，引条款号 |
| 〔监管〕 | 监管规章、通知、办法 | 查原文，引文号 |
| 〔厂商〕 | 厂商公开文档或官方博客 | 查原页，注时点 |
| 〔经验值〕 | 本书实践归纳，无外部出处 | 当假设用，自己校准 |
| 〔建议值〕 | 本书主张的阈值 | 当起点用，按客户裁剪 |

四类之外只剩三种合法形态：算术可复算的换算、案例里的虚构演示值、本书内部指向（第 X 章 / 附录 X / 模板 NN）。

扫描脚本 `scripts/claim_audit.py`。三层豁免：文件级声明（标准件自述“文中阈值均为建议值”）、阈值型断言（含“≥/≤/不超过/建议/阈值”）、结构化块（清单、表格、步骤里的时限）。

**收敛证据**：首跑 102 个无口径块。逐轮修到 0。块数曲线 102 → 52 → 39 → 36 → 22 → 19 → 8 → 4 → 0。

**为什么不是逐条补 URL**：102 个块里大部分不是“缺出处”，是“缺分类”。本书自订的阈值（24 小时内发纪要、60 天内签认）本来就没有外部出处。硬补一个出处，是造假。

**盲区**：脚本只认百分比、倍数、金额、时限四类。“大约三成”“多数客户”这类模糊量词不在扫描范围。防这条靠审阅。

## 九之四、草案徽标（2026-11-10 加）

背景：评估第 11 项。全书 19 处自称“行业标准”。这些标准是本书自订的，没有机构背书。

只改措辞不够。标题、正文、引用三处不同步，读者仍会误读。治法分三层。

1. **标题加标注**：十七份自订标准件的标题以“（拟定稿）”收尾。引用时须连这三个字一起写。
2. **首屏加徽标**：每份草案 H1 下第一行是状态徽标，固定四句。无机构背书、无外部评审、无企业试点、条文可引用可反驳。
3. **门禁拦截**：`content_gate.py` 的 `draft_badge_issues()` 三条规则。标题以“标准”收尾必须有“（拟定稿）”；有“（拟定稿）”必须有徽标；徽标四句不许缺。

**为什么四句都要**：四句分别对应四种被追问的方式。谁背书、谁评过、哪里试过、能不能反驳。删一句，免责就不完整。

**盲区**：门禁只看标题和首屏。正文里写“本标准要求……”不会报错。那是正常用法。真正要防的是拿草案冒充官方标准，这发生在引用环节，靠附录 A.5 的术语约定管。

## 九之五、论证体判据（2026-11-10 加）

背景：评估第 9 项。格言体，结论密度高，论证密度低。典型段落给判断，不给破例，不给边界。

判据是四要素：判断、因果、反例、失效边界。只有判断的是格言，四样齐的是论证。

`content_gate.py` 用两个指标近似。`argument_density` 统计含“因为/所以/意味着/前提/代价/边界”等词的段落占比。`failure_markers` 统计“反例/失效/例外/不适用/误判”的词数。

**为什么不机械替换“要点回顾”**：76/82 文件以“要点回顾”收尾。批量改会造成新的同构，正是“可审计性驱逐可读性”的病根。修法是在论证最薄的章里加“失效边界”节，让论证落在具体段落，不落在模板上。

**判据的边界**：指标高的章不一定好。堆“因为所以”也能刷分。门禁只能筛出明显薄的，不能证明厚的就好。
