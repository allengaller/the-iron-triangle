# 附录 T+　变更落地执行

> 本附录把[附录 T](appx-t-online-change-standard.md)的标准条文转成落地动作。条文定义不在本附录重复。五个动作：受理与定级、评审与签批、窗口实施与值守。验证与回退、关闭归档。分级、原则与红线一律以附录 T 为准。

## T+.1 前置条件与目标

| 前置条件 | 检查内容 | 缺项处理 |
| --- | --- | --- |
| 版本判定 | 公共云版或专有云版明确 | 按 T.5/T.6 对号 |
| 模板就绪 | 模板 18 变更单可用 | 先领模板 |
| 冻结日历 | 年初与客户共同确认 | 先立日历 |
| 预授权清单 | CH4 清单经客户确认 | 先报客户确认 |

完成标志有五项：定级零存疑、三板斧齐、窗口纪律守。验证回退有决断、台账五件齐。

| 目标 | 完成标志 | 主要证据 |
| --- | --- | --- |
| 定级零存疑 | 争议单从高定级 | 变更台账 |
| 三板斧齐 | 缺件不上会 | 评审记录 |
| 窗口纪律守 | 窗口外零实施 | 时间线记录 |
| 验证回退有决断 | 不过即回退 | 回退记录 |
| 台账五件齐 | 监管检查可过 | 变更报告 |

## T+.2 操作一：受理与定级

### 操作步骤

1. 受理变更申请。核对模板 18 字段完整性。
2. 按影响面 × 可逆性定 CH1–CH4（T.4.1）。存疑从高。
3. 核对三板斧：实施方案、验证方案、回退方案。缺件退回。
4. 实施中影响面扩大即升级定级。补齐对应审批再继续。
5. 公共云客户侧变更同样按三板斧执行。不因平台降低要求。

### 预期结果

受理留痕。定级有据。三板斧齐。

### 常见错误

- 定级就低不就高。出事再补审批。
- 三板斧凑数。回退方案没有决策人。

## T+.3 操作二：评审与签批

### 操作步骤

1. CH1/CH2 上变更评审会。双方按需到齐（T.6.1）。
2. 会上过方案、定窗口。明确验证责任人与回退决策人。
3. 签批分级走：CH1 客户管理层、CH2 运维负责人、CH3 简式。
4. 公共云平台变更走确认链：影响分析、客户告知、确认或延期（T.5.2）。
5. 窗口撞客户高峰即提交延期或预约申请。不硬闯。

### 预期结果

评审留痕。签批分级执行。确认与延期有记录。

### 常见错误

- 评审会变通气会。决策人不到场。
- 公共云通告只转发不翻译。客户不知影响。

## T+.4 操作三：窗口实施与值守

### 操作步骤

1. 前 1 个工作日就绪确认。备份完成且恢复验证通过。
2. 窗口内双人复核：一人操作、一人复核。指令复诵确认。
3. TAM 现场或远程值守。专人记录时间线，事后不补记。
4. 灰度首批不排核心与重保客户。主动选靠后批次。
5. 窗口结束未完成即按回退处理。不留半截状态。

### 预期结果

就绪有验证。双人复核执行。时间线完整。

### 常见错误

- 备份没验过恢复。回退时才发现不能用。
- 单人操作图省事。出错无人拦。

## T+.5 操作四：验证与回退

### 操作步骤

1. 按验证方案逐条确认。业务验证由客户方签字。
2. 预留 ≥ 30 分钟回退余量。超时即启动回退决策。
3. 任一条验证不通过即回退。不"带病观察"。
4. 回退按方案执行：触发条件、步骤、时限、决策人四明确。
5. 回退后复盘原因。改进项入风险登记册（模板 09）。

### 预期结果

验证逐条过。回退决策果断。回退有复盘。

### 常见错误

- 验证走过场。观察期当验收。
- 犹豫不回退。错过窗口余量。

## T+.6 操作五：关闭归档与紧急变更

### 操作步骤

1. 变更报告入台账。客户确认关闭。
2. 台账五件齐：申请、审批、实施记录、验证结果、关闭确认。
3. 经验沉淀入案例库（附录 J.8）。
4. 紧急变更 24 小时内补齐评审与签批。次日提交专项说明。
5. 退役类变更按附录 F 时点推动迁移。不可豁免。

### 预期结果

五件齐备。紧急变更手续补齐。退役有迁移计划。

### 常见错误

- 关闭不归档。监管检查临时补。
- 紧急变更不补手续。例外变常态。

## T+.7 验收标准

| 验收项 | 通过标准 | 验证方式 |
| --- | --- | --- |
| 定级 | 存疑从高、升级补批 | 核对变更台账 |
| 三板斧 | 缺件不上会 | 核对评审记录 |
| 签批 | 分级签批留痕 | 核对签批单 |
| 双人复核 | 操作复核分离 | 核对实施记录 |
| 验证回退 | 不过即回退 | 核对回退记录 |
| 台账五件 | 申请到关闭齐 | 核对变更报告 |
| 紧急变更 | 24 小时补手续 | 核对补办记录 |
| 通告触达 | 公共云双百 | 核对通告记录 |

关键项是三板斧、双人复核和台账五件。任一关键项未通过，变更不得视为合格。

## T+.8 执行故障排查

| 症状 | 常见原因 | 处理动作 |
| --- | --- | --- |
| 定级争议 | 标准吃不透 | 存疑从高定级 |
| 回退用不了 | 方案没验证 | 沙盘或演练先行 |
| 窗口超时 | 余量没预留 | 固定留 30 分钟余量 |
| 客户事后才知道 | 通告没翻译 | 影响分析先行 |
| 紧急变更多发 | 常态走例外 | 专项说明加复盘 |
| 台账缺件 | 归档没人管 | 五件齐才许关闭 |

反复出现的问题进入复盘流程（[附录 R](appx-r-problem-retrospective-standard.md)）。

## T+.9 执行检查清单

- [ ] 版本对号（公共云/专有云）
- [ ] 定级存疑从高、扩大即升批
- [ ] 三板斧齐且可执行
- [ ] 评审会决策人到场、签批留痕
- [ ] 就绪确认含恢复验证
- [ ] 双人复核、专人记时间线
- [ ] 验证逐条过、回退余量 ≥ 30 分钟
- [ ] 不过即回退、不带病观察
- [ ] 台账五件齐、客户确认关闭
- [ ] 紧急变更 24 小时补手续

---

**本附录要点回顾**

1. 定级存疑从高。三板斧缺件不上会。
2. 公共云翻译通告，专有云组织评审。两版打法不混用。
3. 双人复核加时间线。窗口结束不留半截状态。
4. 验证不过即回退。回退不是失败，带病上线才是。
5. 台账五件齐。紧急变更 24 小时补手续。
