# 附录 L+　项目导入落地执行

> 本附录把[附录 L](appx-l-project-onboarding-standard.md)的标准条文转成落地动作。条文定义不在本附录重复。五个动作：交接执行、诊断执行、机制落地。验收执行、特殊场景处置。阶段与阈值一律以附录 L 为准。

## L+.1 前置条件与目标

| 前置条件 | 检查内容 | 缺项处理 |
| --- | --- | --- |
| 分类判定 | 三类导入已归类 | 回附录 L.1 |
| 闸门表 | 四阶段出口闸门就绪 | 先抄附录 L.4 |
| 模板 | 模板 01/02/03/09/11 可用 | 先补模板 |
| 接口人 | 双方组织与接口人已定 | 先建接口 |

完成标志有五项：交接签收、诊断确认、机制运行。验收签收、遗留有闭环。

| 目标 | 完成标志 | 主要证据 |
| --- | --- | --- |
| 交接签收 | 材料清单签收 | 交接清单 |
| 诊断确认 | 痛点清单客户确认 | 诊断报告 |
| 机制运行 | 计划签署、例会转起来 | 服务计划 |
| 验收签收 | 七项达标、书面签收 | 验收报告 |
| 遗留有闭环 | 责任人与期限到人到日 | 闭环台账 |

## L+.2 操作一：交接执行

### 操作步骤

1. 交接清单按附录 L.5 的 S1 交付物逐项对。缺项当面记录。
2. 二手项目硬条件：故障史与遗留清单拿不到，记高风险。书面告知客户。
3. 关键人地图初版（模板 11）两周内出。三链录人。
4. 交接签收后建材料台账。缺项挂跟踪。

### 预期结果

清单签收。二手硬条件守住了。地图初版在案。

### 常见错误

- 交接走过场。清单不看就签。
- 二手项目硬接。雷埋进自己手里。

## L+.3 操作二：诊断执行

### 操作步骤

1. 拓扑与监控覆盖核查（对照附录 H）。未覆盖项入风险登记册。
2. 架构健康检查用模板 03 精简版。只查高风险项。
3. 痛点访谈三口（业务、技术、决策）。痛点清单客户书面确认。
4. 风险登记册初版（模板 09）。高风险项指定责任人与应对。

### 预期结果

覆盖核查完成。痛点客户确认。风险册初版成形。

### 常见错误

- 诊断变抄资料。现场没看。
- 痛点不确认。后面反复返工。

## L+.4 操作三：机制落地

### 操作步骤

1. 服务计划（模板 01）签署。目标、节奏、SLA 基线、双方责任四块齐。
2. 例会体系转起来。两轮以上再谈验收。
3. 监控工单接入过附录 H 验收。结论留档。
4. 应急预案初版加一次桌面推演（附录 K）。值班模式生效（附录 I）。

### 预期结果

计划已签。例会转了两轮。接入有结论。推演做过。

### 常见错误

- 计划签完不转。机制停在纸上。
- 推演不做。应急就绪是空话。

## L+.5 操作四：验收执行

### 操作步骤

1. 七项验收逐条测实测值（附录 L.6 锚点）。不带形容词。
2. 遗留问题清单配闭环计划。责任到人、时间到日。
3. 验收报告客户技术负责人书面签收。
4. 未通过即限期整改（建议 ≤ 30 天）后复验。不宣布转稳态。

### 预期结果

七项实测值在案。签收落字。遗留闭环。

### 常见错误

- 实测填“基本达标”。验收失真。
- 未过先转。事故后追责到人。

## L+.6 操作五：特殊场景处置

### 操作步骤

1. 二手项目：观察期 30 天责任边界写进服务计划。定时炸弹三类（临时方案、欠费组件、单点人员）逐项排查。
2. 金融级：S1 加监管摸底，S2 加容灾核查。撞重保先保重保，导入顺延。
3. 存量新系统：S1 可裁剪，S2 诊断与 S3 监控应急接入不裁。

### 预期结果

观察期边界书面。监管摸底齐。裁剪范围明确。

## L+.7 验收标准

| 验收项 | 通过标准 | 验证方式 |
| --- | --- | --- |
| 交接签收 | 清单逐项对、缺项挂跟踪 | 核对交接清单 |
| 二手硬条件 | 故障史与遗留清单到位 | 核对材料台账 |
| 诊断确认 | 痛点客户书面确认 | 核对诊断报告 |
| 机制运行 | 例会 ≥ 2 轮、推演做过 | 核对会议与推演记录 |
| 七项实测 | 锚点达标、实测值在案 | 核对验收报告 |
| 客户签收 | 技术负责人书面签收 | 核对签收页 |
| 遗留闭环 | 责任期限到人到日 | 核对闭环台账 |

关键项是二手硬条件、七项实测和客户签收。任一关键项未通过，项目导入不得视为合格。

## L+.8 执行故障排查

| 症状 | 常见原因 | 处理动作 |
| --- | --- | --- |
| 交接缺材料 | 清单走过场 | 逐项对、缺项跟踪 |
| 二手接手踩雷 | 故障史缺失 | 记高风险书面告知 |
| 验收扯皮 | 实测无数据 | 重测填实测值 |
| 强行转稳态 | 限期整改落空 | 停在整改、不宣布 |
| 机制空转 | 计划签完不管 | 例会两轮硬要求 |
| 监管摸底漏项 | 金融场景套通用流程 | S1 加监管清单 |

反复出现的问题进入复盘流程（[附录 R](appx-r-problem-retrospective-standard.md)）。

- [ ] 痛点清单客户书面确认

- [ ] 例会转满两轮，接入过验收
- [ ] 应急预案初版加一次桌面推演
- [ ] 七项验收实测值在案
- [ ] 验收报告书面签收
- [ ] 遗留问题闭环计划到人到日

---

**本附录要点回顾**

1. 交接先对清单。二手项目硬条件不松口，缺材料就记高风险。
2. 诊断三口访谈，痛点书面确认。机制落地看例会与推演，不看纸面。
3. 验收填实测值。未通过不转稳态，强行转按重大失职追责。
4. 特殊场景三条线：二手看责任边界，金融看监管与重保。存量看裁剪范围。
