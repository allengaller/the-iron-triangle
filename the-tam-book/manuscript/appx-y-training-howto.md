# 附录 Y+　训练操作动作清单

> 本附录把[附录 Y](appx-y-training-tutorial.md) 的每个训练项转成可照做的操作卡。每张卡含动作清单、模板字段和验收标准。训练流程与走法见附录 Y，本附录不重复。编号与附录 Y 一一对应（Y+.1 对 Y.1，以此类推）。

## Y+.1 技术纵深训练操作卡

### 训练一：建立客户技术档案

**模板字段**：

| 字段 | 要点 |
| --- | --- |
| 架构图 | 组件级，含部署形态，能看清核心链路 |
| 版本台账 | 在用组件与停止销售（End of Life，EOL）日期 |
| 配置基线 | 关键配置项 |
| 故障史 | 近 12 个月根因分析（Root Cause Analysis，RCA）记录 |
| 容量基线 | 响应时间、吞吐、资源水位 |
| 业务峰值日历 | 月末、账单日、大促、行情日 |

**验收标准**：

- [ ] 同事 10 分钟内看懂核心链路
- [ ] 档案含至少 3 个已识别风险项

### 训练二：影子评审

**动作清单**：

| 轮次 | 你的动作 | 产出 |
| --- | --- | --- |
| 第 1 次 | 只听。记录关键问题与结论 | 问题清单 + 请教记录 |
| 第 2 次 | 记录并复述结论 | 复述与结论的差异表 |
| 第 3 次 | 主讲一个维度 | 架构师反馈记录 |

**验收标准**：

- [ ] 复述与架构师结论一致度 > 80%〔建议值〕
- [ ] 主讲维度获客户认可

### 训练三：建立故障模式库

**记录字段**：模式名称、触发条件、故障表现。根因分析、预防措施、检测方法。

**动作清单**：每周回顾补充。每月团队分享 1–2 个模式。

**验收标准**：

- [ ] 个人模式库 ≥ 50 个
- [ ] 团队模式库 ≥ 200 个
- [ ] 评审中每月引用 ≥ 3 次

### 训练四：信封背面估算

**动作清单**：选真实场景。记假设。估算。与实测对照校准。更新估算直觉。

**验收标准**：

- [ ] 偏差 < 30%〔建议值〕
- [ ] 2 分钟内给出量级

### 训练五：一页纸评审输出

**一页纸结构**：风险是什么（一句话）；为什么（因果链）；怎么办（整改建议）；不办的代价（业务影响）。

**验收标准**：

- [ ] 每次评审都有一页纸
- [ ] 非技术人员能看懂
- [ ] 客户认可并纳入跟踪

## Y+.2 业务洞察训练操作卡

### 训练一：业务地图绘制

**模板字段**：

| 字段 | 要点 |
| --- | --- |
| 行业 | 银行、证券、保险或支付 |
| 业务主线 | 3–5 条。每条含核心功能、技术依赖、峰值特征 |
| 关键系统 | 核心系统、渠道、风控、监管报送 |
| 业务日历 | 刚性节点、弹性峰值、内部节奏 |

**动作清单**：与客户技术负责人确认。每季度更新。

**验收标准**：

- [ ] 同事 5 分钟看懂核心业务
- [ ] 含至少 3 条业务主线与技术依赖
- [ ] 客户确认准确性

### 训练二：价值翻译练习

**翻译表模板**：

| 技术指标 | 业务影响 | 财务影响 | 数据出处 |
| --- | --- | --- | --- |
| 填一个指标 | 译成业务后果 | 金额或比例 | 底稿或假设依据 |

**动作清单**：选指标。按“技术指标 → 业务影响 → 财务影响”翻译。请客户确认。收集反馈校准。

**验收标准**：

- [ ] 每个指标能译成业务影响
- [ ] 财务影响有出处或假设依据
- [ ] 客户认可准确性

### 训练三：目标挂靠验证

**动作清单**：取客户战略与部门年度目标。列项目。逐项挂目标。问客户“这个项目对部门目标意味着什么”。挂不上的标记。

**验收标准**：

- [ ] 每个项目一句话说清挂靠目标
- [ ] 客户 CIO 层能复述业务价值
- [ ] 挂不上的项目 ≤ 10%

## Y+.3 关系经营训练操作卡

### 训练一：关键人地图绘制

**模板字段**：

| 字段 | 要点 |
| --- | --- |
| 关键人来源 | 项目文档、会议记录、通讯录 |
| 三链标注 | 决策链、影响链、防线 |
| 态度与影响力 | 支持/中立/反对 × 高/中/低 |
| 覆盖频次 | 每月/每季/半年/年度 |
| 接班人 | 每个关键人标注潜在接班人 |

**动作清单**：绘制地图。空白层列入下季度行动计划。

**验收标准**：

- [ ] 覆盖三链
- [ ] 核心客户无单点依赖
- [ ] 每关键人有态度与接班人标注

### 训练二：信任账户管理

**存款动作**：兑现小承诺。先讲坏消息。判断经事实验证后留痕。为客户挡事（内部协调、顶住不合理流程）。

**取款预警**：失约、隐瞒或迟报。让客户在领导面前丢脸。越过接口人告状。为指标好看操纵数据。

**动作清单**：建台账记存取款。每月评估余额。

**验收标准**：

- [ ] 台账完整
- [ ] 存款次数 > 取款次数 × 2
- [ ] 近三月无“让客户丢脸”记录

### 训练三：高层对话模拟

**一页纸模板**：

| 区块 | 内容 |
| --- | --- |
| 【状态】 | 当前系统状态与承诺达成 |
| 【风险】 | 一句话风险 + 时点 |
| 【建议】 | 2–3 个方案，各带代价 |
| 【请求】 | 要客户做什么，期限是什么 |

**动作清单**：备料。找同事扮客户高层。模拟汇报。收集反馈。24 小时内出书面纪要〔建议值〕。

**验收标准**：

- [ ] 一页纸讲清四区块
- [ ] 带 2–3 个方案及代价
- [ ] 24 小时内有书面纪要

## Y+.4 服务治理训练操作卡

### 训练一：服务计划制定

**五构件**：

| 构件 | 要点 |
| --- | --- |
| 服务目标 | 3–5 条，挂在客户业务目标上 |
| 服务范围 | 覆盖系统清单 + 明确不覆盖什么 |
| 节奏表 | 例会、评审、体检、重保、QBR 排期写到日期 |
| 风险与依赖 | 初始风险清单 |
| 交付物清单 | 月报、评审报告、VBR 等，附模板编号 |

**动作清单**：收集输入。按构件编写。与客户接口人会签。

**验收标准**：

- [ ] 五构件齐备
- [ ] 目标挂业务目标
- [ ] 接口人签字

### 训练二：SLA/OLA 谈判模拟

**动作清单**：

1. 校核技术可达性。可用性数学、容量规划、架构评审先过。
2. 明确口径。每个指标写清怎么算、哪取数、谁仲裁。
3. 建立追踪。达成率月报化。

**验收标准**：

- [ ] 指标技术可达
- [ ] 每指标有口径与数据源
- [ ] 客户认可指标

### 训练三：例会体系搭建

**五层节奏**：

| 会议 | 频率 |
| --- | --- |
| 值班晨会 | 每日（重保/驻场期） |
| 服务周会 | 每周 |
| 服务月会 | 每月 |
| 季度业务回顾（Quarterly Business Review，QBR）/高管业务回顾（Executive Business Review，EBR） | 每季 |
| 年度规划会 | 每年 |

**动作清单**：设计节奏。备模板化材料。开首次月会。纪要跟踪行动项。

**验收标准**：

- [ ] 五层完整
- [ ] 会有纪要，行动项责任到人、时间到日
- [ ] 下次会先过上次行动项

## Y+.5 风险与合规训练操作卡

### 训练一：风险登记册建立

**模板字段**：

| 字段 | 要点 |
| --- | --- |
| 风险描述 | 一句话说清“什么条件下会发生什么坏事” |
| 类别 | 技术/业务/组织/合规 |
| 概率 × 影响 | 高/中/低 |
| Owner | 具名负责人 |
| 缓解动作与期限 | 没有缓解动作的不入册 |
| 复审日期 | 每月过册 |

**动作清单**：建册。与客户会签重大风险。每月过册。

**验收标准**：

- [ ] 字段完整
- [ ] 重大风险双方会签
- [ ] 每条有具名 Owner 与期限

### 训练二：三道扫描线执行

| 扫描线 | 内容 |
| --- | --- |
| 技术 | 容量水位、版本生命周期、单点与隐性依赖、配置漂移 |
| 业务 | 业务日历、冻结纪律、容量余量、值守排班 |
| 组织 | 关键人变动、预算收缩、决策链重组、你方人员流失 |

**动作清单**：周快扫、月深扫、季体检。新风险当月入册。

**验收标准**：

- [ ] 三线各有节奏
- [ ] 本月有新风险入册
- [ ] 高危窗口已标注

### 训练三：审计配合模拟

**材料清单**：值班日志、变更台账、演练记录、复盘报告。

**动作清单**：备场景。备材料。扮审计师模拟。收集反馈。

**验收标准**：

- [ ] 30 分钟给出完整证据链
- [ ] 材料如实，不修饰不隐瞒
- [ ] 口径一致

## Y+.6 项目与变革管理训练操作卡

### 训练一：项目节奏把握

**阶段分析字段**：阶段（立项/设计/开发/测试/上线/稳定化）；主要矛盾；TAM 检查点（技术评审、风险登记册、里程碑偏差）。

**先行信号清单**：缺陷重开率上升。变更请求突然增多。决策开始推迟。关键人开始缺席例会。

**动作清单**：分析阶段。识别信号。制定预警机制。

**验收标准**：

- [ ] 说清当前阶段与主要矛盾
- [ ] 识别至少 2 个先行信号
- [ ] 提前 2–4 周预警

### 训练二：Go/No-Go 闸门模拟

**闸门输入清单**：就绪清单完成情况。风险未关闭项（逐项定接受/缓解/阻断）。回退实测记录与耗时。演练结果与遗留问题。监控与告警就绪（含接收人验证）。值守与升级安排。

**量化判据**：高风险项 = 0。回退实测 ≤ 60 分钟。监控覆盖率 100%。

**动作清单**：备输入。定判据。开模拟闸门会。书面记录决策。

**验收标准**：

- [ ] 判据事先量化
- [ ] 决策书面会签
- [ ] 能做出有依据的 No-Go

### 训练三：变革推动模拟

**三类阻力与对策**：

| 阻力 | 表现 | 对策 |
| --- | --- | --- |
| 不会用 | 功能闲置、问题重复 | 赋能与实操培训 |
| 不愿用 | 明用暗绕回旧流程 | 种子用户机制 |
| 不敢用 | 关键操作走旧通道 | 陪跑期设计 |

**动作清单**：识别阻力。定对策。设计采用率指标与跟踪机制。

**验收标准**：

- [ ] 三类阻力各有对策
- [ ] 采用率量化可跟踪
- [ ] 对策与登记册、服务计划联动

## Y+.7 综合演练验收

**输出物清单**：架构评审报告、风险登记册、服务计划初稿。关键人地图、项目里程碑。

**验收表**：

| 输出物 | 验收标准 |
| --- | --- |
| 架构评审报告 | 有分级、有闭环 |
| 风险登记册 | ≥ 10 条，各有 Owner 与期限 |
| 服务计划 | 含年度目标、季度动作、月度跟踪 |
| 关键人地图 | 覆盖决策链、影响链、防线 |
| 项目里程碑 | 可执行，有验收标准 |

## Y+.8 训练运营与排查

### 节奏建议

| 训练 | 频率 |
| --- | --- |
| 故障模式库、信任账户、扫描线 | 持续/每月 |
| 信封背面估算 | 每月 1 次 |
| 价值翻译 | 每月 2 次 |
| 高层对话、目标挂靠 | 每季度 1 次 |
| 一页纸输出 | 每次评审后 |

训练记录归档到培训台账（[附录 J](appx-j-enablement-training-standard.md) 口径）。带教人对训练结果负责。

### 执行故障排查

| 症状 | 常见原因 | 处理动作 |
| --- | --- | --- |
| 训练坚持不下来 | 无固定节奏 | 绑定月度日历 |
| 档案越写越像文档 | 无提炼标准 | 对照字段表重写 |
| 模式库变僵尸库 | 不回顾不引用 | 每周回顾 + 评审引用 |
| 客户退回价值翻译 | 财务影响没出处 | 补底稿再送 |
| 高层对话冷场 | 只带问题不带方案 | 强制三方案模板 |
| 闸门模拟放水 | 判据现场议 | 判据先量化后开会 |
| 台账只记存款 | 对取款不敏感 | 每月做余额评估 |
| 验收总是走过场 | 无对照标准 | 逐条对附录 Y+ 验收表 |
