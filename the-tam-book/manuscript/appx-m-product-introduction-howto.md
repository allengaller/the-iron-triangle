# 附录 M+　产品导入落地执行

> 本附录把[附录 M](appx-m-product-introduction-standard.md)的标准条文转成落地动作。条文定义不在本附录重复。五个动作：导入推进、转移执行、认证执行、准入验收、AI 专项执行。阶段与锚点一律以附录 M 为准。

## M+.1 前置条件与目标

| 前置条件 | 检查内容 | 缺项处理 |
| --- | --- | --- |
| 接收方 | 能力接收方书面指定 | 先定团队 |
| 范围 | 转移范围与裁剪书面确认 | 先签范围 |
| 环境 | 非生产实操环境就绪 | 先搭仿真 |
| 模板 | 模板 02/03/04 可用 | 先补模板 |

完成标志有五项：五阶段过闸、四层转移完、认证双人。准入签收、资产入库。

| 目标 | 完成标志 | 主要证据 |
| --- | --- | --- |
| 五阶段过闸 | PL1–PL5 出口全过 | 阶段闸门记录 |
| 四层转移完 | 运维/配置/开发/管理齐 | 转移清单 |
| 认证双人 | 关键操作每项 ≥ 2 人 | 认证档案 |
| 准入签收 | 五项达标、书面签收 | 准入报告 |
| 资产入库 | 文档与提示词入版本管理 | 资产台账 |

## M+.2 操作一：导入推进

### 操作步骤

1. PL1 能力清单与业务场景映射，客户书面确认。关键指标基线写到数。
2. PL2 环境核查表逐项过。承载平台过附录 H 验收。
3. PL3 部署记录可复现。配置项入 CMDB。
4. PL4 验证三件：功能用例、性能压测、切换实测。
5. PL5 闸门全项闭环（模板 04）。回退方案先演练后放行。

### 预期结果

五道闸门全过。基线可测。回退演练过。

### 常见错误

- 基线写“性能良好”。验收时无据可测。
- 回退没演练。上线即裸奔。

## M+.3 操作二：转移执行

### 操作步骤

1. 转移清单按四层排（附录 M.6.1）。裁剪项客户书面同意。
2. 文档先行。活文档入知识库，不发一次性 PDF。
3. 联合值守期 ≥ 4 周。客户工程师从观察岗转主值，厂商退备值。
4. 故障实战学分：真实事件主导处置 ≥ 1 次。无事件用模拟演练补。

### 预期结果

四层清单齐。文档活。责任过渡完成。

### 常见错误

- 文档一交了之。客户没人会实操。
- 联合值守走过场。厂商一直主值，过渡没发生。

## M+.4 操作三：认证执行

### 操作步骤

1. 认证按附录 J 三段式。笔试、实操答辩、实战评估。
2. 主备两人原则硬执行。关键操作每项至少两人过认证。
3. 认证档案记层级与操作项。缺口清单进追赶计划。
4. 培训不以签到表结项。认证才算数。

### 预期结果

双人覆盖。认证档案齐。缺口有计划。

### 常见错误

- 签到表当转移凭证。会后没人会。
- 单点通过。人一走能力归零。

## M+.5 操作四：准入验收

### 操作步骤

1. 五项验收逐条测实测值（附录 M.7 锚点）。
2. 支撑通道书面确认。客户知晓何时找厂商。
3. 准入报告双方签收。未过则值守期延长（≤ 30 天）复验。
4. 未准入不撤支持。撤出即按重大失职追责。

### 预期结果

五项实测达标。签收落字。支持撤出有底气。

### 常见错误

- 验收走过场。依赖悄悄留下。
- 未准入先撤。出事两头挨打。

## M+.6 操作五：AI 专项执行

### 操作步骤

1. 评估集随 PL4 移交。教客户维护评估集。
2. 失效模式告知进管理层材料。幻觉与漂移的监控手段交底。
3. 提示词、检索配置、护栏规则入版本管理（附录 H5.6-4）。
4. 成本运营转移：客户能独立读成本账单、看容量瓶颈。
5. 金融客户合规逐项书面确认（第 16、24 章口径）。

### 预期结果

评估集可维护。失效模式交了底。资产入了库。合规签了字。

### 常见错误

- 评估集不留。上线后效果漂移没人测。
- 成本账没人会读。账单爆了才找厂商。

## M+.7 验收标准

| 验收项 | 通过标准 | 验证方式 |
| --- | --- | --- |
| 五阶段闸门 | 出口全过、书面结论 | 核对阶段记录 |
| 转移清单 | 四层齐、裁剪书面同意 | 核对清单 |
| 文档资产 | 活文档入知识库 | 核对知识库 |
| 双人认证 | 关键操作每项 ≥ 2 人 | 核对认证档案 |
| 实战学分 | 主导处置 ≥ 1 次 | 核对处置记录 |
| 准入五项 | 实测达标、书面签收 | 核对准入报告 |
| AI 专项 | 五项全落地 | 核对移交清单 |

关键项是双人认证、准入签收和 AI 专项（适用时）。任一关键项未通过，产品导入不得视为合格。

## M+.8 执行故障排查

| 症状 | 常见原因 | 处理动作 |
| --- | --- | --- |
| 交付即依赖 | 转移没做 | 补四层清单重走 |
| 客户没人会 | 签到表结项 | 改认证结项 |
| 单点人员依赖 | 只训一人 | 主备两人硬执行 |
| 效果漂移无人测 | 评估集没移交 | 补评估集与维护培训 |
| 账单争议 | 成本运营没转移 | 补成本交底 |
| 合规卡壳 | 书面确认缺 | 逐项补签 |

反复出现的问题进入复盘流程（[附录 R](appx-r-problem-retrospective-standard.md)）。

- [ ] 五阶段闸门全过、回退演练过

- [ ] 活文档入知识库
- [ ] 联合值守 ≥ 4 周，责任过渡完成
- [ ] 关键操作双人认证
- [ ] 实战学分达标
- [ ] 准入五项实测、双方签收
- [ ] AI 专项五项落地（适用时）
- [ ] 支撑通道书面确认

---

**本附录要点回顾**

1. 五阶段闸门硬执行。基线可测、回退演练过。
2. 四层转移以认证结项，不以签到结项。主备两人防单点。
3. 准入是终点。未准入不撤支持，撤了按重大失职追责。
4. AI 产品五项叠加。评估集、失效模式、提示词资产。成本运营、合规确认。
