# 第 35 章　度量实施动作

> 本章把[第 34 章](ch34-measurement-system.md)的指标口径转成落地动作。口径定义不在本章重复。本章解决八个操作，分两组。第一组建基础：统一口径、补齐取数、健康分运营。第二组管使用：达成管理、事件效率、调研、价值沉淀、指标治理。

## 35.1 前置条件与目标

开始前确认以下输入。缺项时先补齐，或登记为风险。

| 前置条件 | 检查内容 | 缺项处理 |
| --- | --- | --- |
| 口径表 | 第 34 章口径已抄进服务计划附件 | 先统一口径再谈考核 |
| 取数能力 | 考核指标可从系统自动获取 | 取不到的标记“监测项” |
| 仲裁机制 | 口径争议的仲裁人已明确 | 指定服务经理或客户接口 |
| 模板 | [模板 10](tpl-10-customer-health-scorecard.md)、[模板 15](tpl-15-tam-service-quality-scorecard.md) 可用 | 先补齐模板 |
| 评审节奏 | 指标季度评审排进日历 | 建立季度评审会 |

完成标志有六项：口径统一、取数就绪、健康分运转、月报出数、抽查执行、退休机制生效。

| 目标 | 完成标志 | 主要证据 |
| --- | --- | --- |
| 口径统一 | 同名指标一个口径 | 口径表与对齐记录 |
| 取数就绪 | 考核指标系统出数 | 数据链路核对记录 |
| 健康分运转 | 月度刷新且阈值有动作 | 模板 10 台账 |
| 月报出数 | SLA 与效率指标月报化 | 月报存档 |
| 抽查执行 | 季度抽查有记录 | 抽查台账 |
| 退休生效 | 评审有纪要、退休有记录 | 评审纪要 |

## 35.2 操作一：统一口径落地

### 操作步骤

1. 把第 34 章口径表抄进服务计划附件（[模板 01](tpl-01-service-plan.md)）与考核文件。
2. 逐指标核对分子分母、取数系统、仲裁人。
3. 消除同名不同算：附录 G/I/K/P/Q 与模板 10/15 的口径逐条对齐。
4. 口径争议当天升级仲裁。仲裁结果回写口径表。

### 预期结果

同名指标全书一个口径。争议有仲裁人，仲裁结果有记录。

### 常见错误

口径表抄完就锁抽屉。争议各算各的。

## 35.3 操作二：补齐取数与平台证据

### 操作步骤

1. 对照[附录 H](appx-h-tool-platform-acceptance-standard.md) 验收平台证据能力。
2. 取不到数的指标标记“监测项”，暂不考核。
3. 手工填报只作过渡。过渡期数据标注来源。
4. 每季度复核取数缺口，补一个消一个。

### 预期结果

考核指标全部系统出数。监测项清单逐季变短。

### 常见错误

把监测项硬塞进考核。手工数据不标注来源。

## 35.4 操作三：客户健康分运营

### 操作步骤

1. 月度刷新五维分数（[模板 10](tpl-10-customer-health-scorecard.md)），每维下钻到原始证据。
2. 转黄 48 小时内完成健康检查并约客户管理层。
3. 转红 24 小时内上报。连续降档强制触发[附录 R](appx-r-problem-retrospective-standard.md) 客情复盘。
4. 恢复定绿前核对上轮动作证据。
5. 健康分不作唯一续约预测依据。

### 预期结果

分数月月可解释。阈值触发必有动作，动作有记录。

### 常见错误

打分凭印象。阈值触发无人接。只在续约前突击刷新。

## 35.5 操作四：SLA 达成管理

### 操作步骤

1. 达成率月报化，按服务、按客户分别出数。
2. 设预警线（如距阈值还剩 20% 余量）。触发即启动动作。
3. 违约确认后协助申领 SLA Credit。时限 ≤ 5 个工作日。
4. 监测覆盖 100%，不等客户自己发现违约。
5. 计划内维护剔除按合同执行。合同未写明的，当季补签。

### 预期结果

达成率提前预警，违约主动发现。Credit 申领在时限内完成。

### 常见错误

只盯达标率数字，不看余量预警。违约后才补救。Credit 申领拖过时限。

## 35.6 操作五：事件效率指标使用

### 操作步骤

1. MTTR 分级分客户看趋势，不做绝对值横比。
2. 防“降级定级”：定级按[第 25 章](ch25-financial-incident.md)执行。复盘核查按[附录 R](appx-r-problem-retrospective-standard.md)执行。
3. MTBF 长期走高时审计告警阈值。排除阈值调钝的假稳定。
4. 复发率按 90 天窗口滚动统计，目标 0。

### 预期结果

趋势可信，定级无水分。MTBF 走高能区分真稳定与假稳定。

### 常见错误

拿绝对值排名刺激团队。MTBF 走高就宣布稳定，不查告警阈值。

## 35.7 操作六：感知调研执行

### 操作步骤

1. CSAT 事件后即时投放。CES 季度抽样。NPS 半年或年度投放。
2. 单客户 NPS 样本 < 5 时只看不考核。
3. 低分必须回访。附言指向具体事件的，转[附录 R](appx-r-problem-retrospective-standard.md) 客情复盘。
4. 禁止求高分话术与挑客户投放问卷。

### 预期结果

三指标按频率出数。低分有回访闭环，无投放污染。

### 常见错误

问卷集中轰炸。低分无人跟。把 NPS 当季度考核硬指标。

## 35.8 操作七：价值度量与 VBR 沉淀

### 操作步骤

1. 三类价值指标分别建测算依据。不许拍脑袋。
2. 归因写“贡献”不写“功劳”。
3. 价值内容进 QBR/EBR（[模板 08](tpl-08-qbr-ebr-template.md)）。一年至少沉淀一份 VBR。
4. 价值证据对齐[附录 G](appx-g-tam-work-evaluation-standard.md) L3.7 的考核要求。

### 预期结果

价值数字有底稿，归因经得起追问。年度 VBR 按期沉淀。

### 常见错误

价值拍脑袋。把贡献写成功劳。VBR 只在续约前赶工。

## 35.9 操作八：防异化审计与指标退休

### 操作步骤

1. 效率指标逐个检查配对质量指标。MTTR 配复发率，响应速度配一次解决率。
2. 季度按比例抽查原始记录，与上报值核对。造假适用[附录 G](appx-g-tam-work-evaluation-standard.md) 红线。
3. 考核锚点用“逐季改善或优于基线”，不用绝对值横比。
4. 连续四季稳定达标且无决策价值的指标，降级为监测项。
5. 季度评审指标本身。从没驱动过决策的指标，退休它。

### 预期结果

配对指标齐备。抽查有记录。指标清单只减不膨胀。

### 常见错误

抽查走过场。退休阻力大就放弃。指标坏了先改目标不改口径。

## 35.10 验收标准

| 验收项 | 通过标准 | 验证方式 |
| --- | --- | --- |
| 口径统一 | 同名指标口径一致，无同名不同算 | 抽查附录与模板引用 |
| 取数 | 考核指标全部系统出数 | 核对数据链路 |
| 健康分 | 月度刷新，阈值动作有执行记录 | 抽查健康检查记录 |
| SLA | 月报出数，预警线有动作 | 核对月报与动作台账 |
| 事件效率 | 分级分客户看趋势，定级无水分 | 抽查定级与复盘 |
| 感知调研 | 按频率投放，低分有回访 | 核对问卷与回访记录 |
| 价值度量 | 年度 VBR 沉淀，归因有依据 | 核对 VBR 与测算底稿 |
| 防异化 | 抽查执行，配对指标齐备 | 核对季度抽查记录 |
| 指标治理 | 季度评审有纪要，退休有记录 | 核对评审纪要 |

关键项是口径统一、取数、健康分和防异化。任一关键项未通过，度量体系不得视为合格。

## 35.11 执行故障排查

| 症状 | 常见原因 | 处理动作 |
| --- | --- | --- |
| 同名指标对不上 | 口径未统一 | 回写口径表并重算 |
| 指标出数延迟 | 取数链路靠手工 | 排入平台整改 |
| 健康分虚高 | 打分不下钻证据 | 重开证据抽查 |
| SLA 争议扯皮 | 维护剔除未写进合同 | 补签合同条款 |
| MTTR 突然变好 | 降级定级 | 复盘核查定级 |
| MTBF 走高、告警变少 | 阈值调钝 | 审计告警质量 |
| NPS 异常高 | 挑客户投放 | 重投放并记录 |
| 客户质疑价值报告 | 归因夸大 | 改写为贡献口径 |
| 报表越做越多 | 指标只增不减 | 启动退休评审 |

反复出现的问题进入复盘流程。

## 35.13 AI 时代的执行增量

取数脚本可以由 AI 生成，还带校验语句。按口径表写出分子分母的查询。先在监测项上试跑，跑通再进考核链路。

健康分月报先由模型出草稿。五维分数、阈值动作与趋势说明按模板 10 排好。模型不下健康结论，TAM 补证据再发。

指标异化的异常模式由 AI 识别。MTTR 单边向好而复发率不动，这类配对背离先标出来。标出的项送季度抽查，不直接定性。

口径变更一律走双跑校准。AI 生成的新算法与旧口径并行跑一段。两套数都留档，差异解释清楚才切换。

AI 不得改口径定义。分子分母、取数系统与仲裁人只在口径表里改。改完回写服务计划附件。口径唯一事实源在第 34 章。

没变的是仲裁与评审。口径争议仍当天升级仲裁，指标退休仍由季度评审定。模型只提供线索与草稿。

一条边界：AI 生成的取数脚本先校验再上线。校验不过标监测项，不进考核。指标异化的定性仍由人抽查原始记录。

---

**本章要点回顾**

1. 落地第一步是统一口径。抄进服务计划与考核文件，消除同名不同算。
2. 取数只认系统。取不到数的先标监测项，不硬考核。
3. 健康分的灵魂是阈值动作。转黄 48 小时、转红 24 小时。恢复定绿看证据。
4. SLA 管理做在违约前：月报化加预警线。Credit 协助申领 ≤ 5 个工作日。
5. 事件指标看趋势不看横比，防降级定级和阈值调钝两种假象。
6. 感知调研三频率三纪律，低分必回访。价值归因写贡献不写功劳。
7. 指标治理闭环：配对制衡、季度抽查、退休机制。报表为决策服务，不为考核打工。
