## 12.1 服务计划制定

### 定位

服务计划是单一客户年度服务工作的总纲（流程 P1，[模板 01](tpl-01-service-plan.md)）。它回答五个问题。做什么、做到什么程度、谁来做、什么时候做、怎么算做好。

### 必备构件

| 构件 | 内容要点 | 常见错误 |
|------|----------|----------|
| 服务目标 | 3–5 条，挂在客户业务目标上（[第 7 章](ch07-business-insight.md)目标挂靠） | 写成“做好服务工作”式空话 |
| 服务范围 | 覆盖系统清单 + 明确不覆盖什么 | 范围无界，出事全是你的 |
| 节奏表 | 例会、评审、健康检查、重保、QBR 的年度排期 | 只有频次没有日期，季度末全堆一起 |
| 风险与依赖 | 初始风险清单（转入风险登记册，流程 P9） | 风险写成免责声明 |
| 交付物清单 | 月报、评审报告、VBR 等，附模板编号（模板 01/03/08） | 交付物无验收标准 |

### 运行纪律

- **年度制定、季度刷新**：业务日历（[第 7 章](ch07-business-insight.md)）变了要触发刷新。组织架构变了、系统清单变了同样要刷新。刷新记录本身就是治理证据（[附录 G](appx-g-tam-work-evaluation-standard.md) L2.1 的核查点）；
- **与客户共同签署**：服务计划不是单方宣言。客户接口人签字确认范围与节奏，后续争议时它是“宪法”；
- **计划即承诺**：计划里写了的必须做到或正式变更。写了不做比不写更伤信任（[第 9 章](ch09-relationship-management.md)账户模型）。

### 操作步骤

1. **收集输入**：客户业务目标、系统清单、业务日历、历史服务记录。
2. **制定目标**：3–5 条，每条挂在客户业务目标上。
3. **明确范围**：覆盖系统清单 + 明确不覆盖什么。
4. **排定节奏**：例会、评审、健康检查、重保、QBR 的年度排期。
5. **识别风险**：初始风险清单，转入风险登记册。
6. **列出交付物**：月报、评审报告、价值实现报告（Value Realization Report，VBR）等，附模板编号。
7. **客户确认**：与客户接口人共同签署。
8. **季度刷新**：每季度回顾并刷新。

### 预期结果

五构件齐备。目标挂业务目标。接口人签字。季度刷新有记录。

## 12.2 SLA / OLA / XLA 谈判与管理

### 概念与分工

- **SLA（服务等级协议）**：对客户的承诺——可用性、响应时限、恢复时限。SLA 是合同语言，违约有真金白银的 SLA Credit（口径见[第 34 章](ch34-measurement-system.md)）；
- **OLA（运营等级协议）**：对内部团队的承诺。为支撑 SLA，研发、支持、运维各有自己的时限与质量要求。**SLA 是对外的脸面，OLA 是对内的传动轴**。SLA 达标而 OLA 长期失守，说明你在透支内部团队守承诺，迟早断链；
- **XLA（体验等级协议）**：对体验的度量——CSAT/NPS、端到端业务成功率、告警噪声比。SLA 全绿但用户骂声一片的“西瓜指标”（外绿内红）正是 XLA 要抓的。

### TAM 的四个动作

1. **谈判期介入**：销售签合同前，TAM 必须校核 SLA 的技术可达性。承诺 99.99% 却只规划单机房。合同数字上就不成立（[第 5 章](ch05-technical-depth.md)可用性数学）。签之前拦下来是你的责任；
2. **口径管理**：每个 SLA 指标写清三件事。怎么算（分子分母）、从哪取数（系统记录为准）、谁仲裁争议。口径不前置，违约时全是扯皮；
3. **达成追踪**：SLA 达成率月报化。逼近阈值提前告警并启动动作。不要等违约后写检讨；
4. **OLA 反向治理**：定期把内部环节的失守数据摆上例会。内部传动轴不保养，SLA 违约只是时间问题。

### 操作步骤

1. **校核 SLA 技术可达性**：可用性数学、容量规划、架构评审。
2. **明确口径**：每个指标写清“怎么算、哪取数、谁仲裁”。
3. **建立追踪机制**：SLA 达成率月报化。
4. **定期回顾 OLA**：内部环节失守数据上例会。
5. **引入 XLA**：CSAT/NPS、端到端业务成功率、告警噪声比。

### 预期结果

指标技术可达。口径表前置。达成率月报化。OLA 失守数据上过例会。

## 12.3 变更与发布治理

### 变更三问

任何变更先答三问。改什么（范围与影响面）、凭什么现在改（窗口依据）。错了怎么办（回退方案）。三问答不齐，变更不上会。

### 变更分级与窗口

- **分级**：按影响面与风险分级（标准变更/重要变更/紧急变更）。级别决定审批深度与会审阵容；
- **窗口纪律**：金融客户的变更窗口以业务日历划定（[第 7 章](ch07-business-insight.md)）。冻结期（年终决算、重保期、监管检查期）内只放行紧急变更。紧急变更必须事后复盘“为什么没提前想到”（[第 23 章](ch23-financial-availability.md)、[第 24 章](ch24-major-assurance.md)；现场纪律见[附录 B](appx-b-tam-process-system.md) B.3.5）；
- **灰度与回退纪律**：先小流量验证再全量。回退方案必须可执行且演练过。写了“回退方案：重新部署旧版本”。但没验证过数据兼容性。等于没有回退（[第 23 章](ch23-financial-availability.md)）。

### TAM 的位置

TAM 通常不是变更的审批人，而是**变更的质检员**。质检三件事：三问答齐、窗口合规、相关方知情。重大变更叠加上线闸门（流程 P4，[模板 04](tpl-04-go-nogo-gate-checklist.md)）时，TAM 有建议权甚至唱票权。授权边界见[附录 N](appx-n-tam-onsite-certification.md)。

### 操作步骤

1. **接收变更申请**：收集变更范围、影响面、窗口依据。
2. **变更三问审核**：改什么、凭什么现在改、错了怎么办。
3. **窗口合规检查**：是否业务日历冻结期、是否已报备。
4. **相关方知情确认**：客户、内部团队、第三方。
5. **变更实施跟踪**：监控实施过程，记录偏差。
6. **变更后复盘**：紧急变更必须复盘“为什么没提前想到”。

### 预期结果

变更三问答齐。窗口合规。相关方知情。紧急变更有复盘。

## 12.4 配置与资产可视

治理的底座是“知道客户在跑什么”。配置与资产台账四张表：

### 四张表

| 表 | 内容 | 数据源 |
|----|------|--------|
| 系统清单 | 系统名、等级、责任人、架构版本 | CMDB |
| 版本基线 | 各组件版本、补丁状态、EOS/EOL 日期 | 厂商通告 + 系统扫描 |
| 配置基线 | 关键参数基线值，漂移检测周期 | 配置管理系统 |
| 容量水位 | 核心资源当前水位与扩容阈值 | 监控系统 |

### 操作步骤

1. **建立台账**：从 CMDB、监控系统、配置管理系统中取数。
2. **设定基线**：为每个系统设定版本、配置、容量基线。
3. **漂移检测**：定期检查实际值与基线的偏差。
4. **更新台账**：变更后及时更新，确保台账最新。

### 预期结果

四张表齐备。数据来自系统而非记忆。漂移检测有节奏。

## 12.5 例会体系

例会是治理的心跳。推荐五层节奏（按客户等级裁剪，长尾客户可合并）：

| 会议 | 频次 | 参加方 | 核心议程 |
|------|------|--------|----------|
| 值班晨会 | 每日（重保/驻场期） | 值班与驻场 | 过夜事件、当日风险、交接确认（[附录 I](appx-i-on-duty-standard.md)） |
| 服务周会 | 每周 | 客户接口人 | 工单与事件进展、变更排期、行动项跟踪 |
| 服务月会 | 每月 | 客户管理层 | 月报：SLA、健康分、风险登记册、下月计划 |
| QBR/EBR | 季度 | 决策层 | 价值实现、规划对齐（[第 21 章](ch21-commercial-synergy.md)，流程 P8） |
| 年度规划会 | 每年 | 双方高层 | 服务计划续签、目标刷新 |

### 三条纪律

1. **无纪要不散会**：纪要不是记录是契约。行动项责任到人、时间到日。下次会议第一件事是过上次行动项。闭环率是最诚实的治理指标；
2. **材料模板化**：月报、QBR 用固定模板（[模板 08](tpl-08-qbr-ebr-template.md)），可比性来自格式稳定。团队内部的日/周/季/年报另成一轨。结构、判定线与反二传手规则见[附录 AA](appx-aa-tam-reporting-standard.md)。主 TAM 用 RP1–RP4，成员用 RP5–RP8；
3. **会可少开，节奏不可断**：议程空转时，取消当次会议并书面说明。节奏断档（连续两次不开）是治理失效的先行指标。

### 操作步骤

1. **制定会议计划**：按客户等级确定会议频次和参加方。
2. **准备会议材料**：模板化，确保可比性。
3. **召开并记录**：无纪要不散会，行动项责任到人。
4. **跟踪行动项**：下次会议第一件事是过上次行动项。
5. **定期回顾**：季度回顾会议效果，调整节奏。

### 预期结果

五层节奏不缺。每次会有纪要。行动项闭环率 ≥ 90%。

## 12.6 服务质量度量

SLA 是契约底线，不是质量的全部。12.2 的“西瓜指标”就是证明。SLA 全绿，客户照样骂。治理体系还需要一把统一的质量尺。它把“服务好不好”从感觉变成分数。本书的答案是[附录 P](appx-p-tam-service-quality-standard-public-cloud.md)/[附录 Q](appx-q-tam-service-quality-standard-dedicated-cloud.md)的服务质量标准。按交付形态分两个版本，共用一套框架：

- **公共云五维**（附录 P）：响应与事件、主动服务、变更与通告。服务节奏、结果与感知。核心立场：TAM 不背基础设施可用性。那是厂商公开 SLA 的事。但 TAM 背 SLA 达成监测与 Credit 申领协助。厂商通告只转发原文不算触达。必须附客户环境影响分析；
- **专有云六维**（附录 Q）：共用框架上多出两维。一是平台运行质量：可用性共担、容量水位、备份恢复验证。二是合规与审计支持：等保配合、监管上报、数据分级分类执行。核心立场：责任共担边界逐层写进服务计划。边界没写清视同该项质量不达标。

三条度量纪律（两版一致）：

1. **只认系统记录**：指标从工单、监控、CMDB 取数。平台要求见[附录 H](appx-h-tool-platform-acceptance-standard.md)。手工填报不算数。取不到数的指标宁可不纳入考核，也不放开口子；
2. **节奏固定**：月度内部自评。季度随 QBR 向客户公开质量得分。年度按实测基线校准锚点。服务质量与服务计划一样是可刷新契约。不是年终一次性审判；
3. **与评估同源**：质量得分是[附录 G](appx-g-tam-work-evaluation-standard.md) 的 L2/L3 取数口径之一。共用数据源、不重复填报。服务质量标准管“客户得到了什么”。附录 G 管“人干得怎么样”。别混为一谈。

AI 在本节的位置是背景板，不是裁判。异常检测把“哪个指标在悄悄变差”从月度人工比对里捞出来；趋势预测给健康分提前量；取数脚本的自动校验减少口径两张皮的机会。三条纪律不因 AI 松动：数仍只从系统取，口径仍只在[第 34 章](ch34-measurement-system.md)改，打分仍是人对锚点的判断。AI 改变的是发现异样的速度，不改变“什么算数”的定义。

打分工具是[模板 15](tpl-15-tam-service-quality-scorecard.md)（服务质量记分卡，双版本）。先核四条红线：伪造数据、隐瞒事件、越权访问。通告不触达或未授权变更也算。触发即当期不合格。再逐条目对锚点打达标/不达标。

### 操作步骤

1. **选择版本**：公共云五维或专有云六维。
2. **建立数据源**：从工单、监控、CMDB 取数。
3. **月度自评**：按模板 15 逐条目打分。
4. **季度公开**：随 QBR 向客户公开质量得分。
5. **年度校准**：按实测基线校准锚点。
6. **红线核查**：伪造数据、隐瞒事件、通告不触达、越权访问。

### 预期结果

版本选对、数据可取。月度有自评、季度有公开。红线四条无人碰。

### 常见错误

- 数据手工填报，口径两张皮。
- 得分只内部看，客户不知道。
- 红线核查走过场。

## 12.7 验收标准

| 验收项 | 通过标准 | 验证方式 |
| --- | --- | --- |
| 服务计划 | 五构件齐备、双方签署、季度刷新 | 核对计划与签署页 |
| 口径管理 | 每指标答得出怎么算、哪取数、谁仲裁 | 抽查口径表 |
| 变更治理 | 三问答齐、窗口合规、有复盘 | 抽查变更记录 |
| 资产台账 | 四张表齐、数据来自系统 | 核对台账 |
| 例会体系 | 节奏不缺、纪要齐全、闭环率 ≥ 90% | 核对纪要 |
| 服务质量 | 模板 15 逐季出分、红线无触发 | 核对记分卡 |

关键项是服务计划、口径管理和例会体系。任一关键项未通过，服务治理实战不得视为合格。

## 12.8 执行故障排查

| 症状 | 常见原因 | 处理动作 |
| --- | --- | --- |
| 计划签完没人看 | 没绑例会 | 把计划刷新排进季度议程 |
| SLA 争议扯皮 | 口径不前置 | 补口径表并书面确认 |
| OLA 长期失守 | 内部不认账 | 失守数据上例会 |
| 变更总出事故 | 三问走过场 | 重建质检纪律 |
| 台账和现场对不上 | 变更后不更新 | 变更闭环挂台账更新 |
| 例会变成一言堂 | 纪要没行动项 | 责任到人、时间到日 |
| 质量得分虚高 | 手工填报 | 换系统取数 |

反复出现的问题进入复盘流程（[附录 R](appx-r-problem-retrospective-standard.md)）。

## 12.9 执行检查清单

- [ ] 服务计划最新（本季度刷新过），客户接口人已确认
- [ ] 计划里每个目标都能挂到客户业务目标
- [ ] 每条 SLA 都能答出“怎么算、哪取数、谁仲裁”
- [ ] OLA 失守数据上过例会，不是只在内部忍
- [ ] 近三个月变更都能过“三问”回测，冻结期纪律无例外
- [ ] 四张台账齐全，数据来自系统而非记忆
- [ ] 例会纪要有行动项，闭环率 ≥ 90%，节奏无断档
- [ ] 服务质量得分能按附录 P/Q 逐季打出（模板 15）；数据来源全部系统可取
- [ ] 我休假两周，服务质量不依赖我在场

---

**本章要点回顾**

1. 服务计划五构件。三个运行纪律：季度刷新、共同签署、计划即承诺。
2. SLA 对外、OLA 对内、XLA 对体验。口径先于数值，达成要月报化。
3. 变更三问答不齐不上会。回退没演练等于没回退。TAM 是质检员不是审批人。
4. 治理底座是四张台账。数据来自系统，变更后即更新。
5. 例会是心跳：无纪要不散会、材料模板化、节奏不可断。
6. 服务质量按附录 P/Q 打分。红线四条零容忍。与评估同源，不重复填报。
