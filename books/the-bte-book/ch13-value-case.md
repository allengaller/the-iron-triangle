# 第 13 章　价值假设与业务案例

> 客户立项，不靠厂商 PPT。客户要拿一份能过内部评审的业务案例。BTE 的任务，是帮客户把价值假设变成客户愿意签字的账。本章给六个动作：立假设、找基线、算三笔账、写立项材料、过评审、设验证。

## 13.1 前置条件与目标

| 前置条件 | 检查内容 | 缺项处理 |
| --- | --- | --- |
| 需求基线 | 场景与五要素已签认 | 先回第 12 章 |
| 业务数据 | 现状指标、成本、损失 | 先向客户取数 |
| 财务口径 | 客户怎么算账 | 先问财务 |
| 决策场景 | 这份案例支持什么决定 | 先问用途 |
| 方案轮廓 | 能力范围与边界 | 先与 SA 对齐 |

完成标志有五项：假设四段齐全；基线客户确认；三笔账有依据；立项材料客户可用；验证方式已定。

| 目标 | 完成标志 | 主要证据 |
| --- | --- | --- |
| 假设清楚 | 问题、能力、后果、价值四段 | 价值假设表 |
| 基线可信 | 指标、口径、年份客户确认 | 基线记录 |
| 账算得平 | 收益、成本、风险三笔账 | 业务案例 |
| 客户可用 | 客户能拿去内部立项 | 立项材料 |
| 验证可跟踪 | 承诺值与取数方式明确 | 验证表 |

## 13.2 操作一：立价值假设

### 步骤

1. 写问题：谁，在什么场景，损失什么；
2. 写能力：我们做什么，不做什么；
3. 写后果：客户哪个指标会变；
4. 写价值：这个变化值多少钱或降多少风险；
5. 四句话连读，读不通就重写。

### 预期结果

团队能用四句话讲清价值，不依赖 PPT。

### 常见错误

- 问题写成“客户要数字化”；
- 能力写成“提供领先方案”；
- 后果写成“提升效率”；
- 价值写成“意义重大”。

## 13.3 操作二：找基线

### 步骤

1. 选 1–3 个关键指标，不贪多；
2. 每个指标写口径、时间窗、取数系统；
3. 取最近 12 个月数据，标季节性与异常；
4. 请客户对口人确认；
5. 不确定的给区间，不给点值。

### 预期结果

客户认可“现在是什么样”，后续收益可验证。

### 常见错误

- 用行业平均值代替客户基线；
- 口径不清，双方各算一套；
- 只取最好月份。

## 13.4 操作三：算三笔账

### 步骤

1. 收益账：收入、成本、风险、合规与体验四类；
2. 成本账：采购、实施、运营、变更、退出五类；
3. 风险账：关键假设、失败模式、缓解动作；
4. 每笔账标事实、估算、判断三层；
5. 给区间，不给单点。

### 预期结果

客户能看到赚多少、花多少、可能亏在哪。

### 常见错误

- 只算收益，不算成本与风险；
- 把判断写成事实；
- 收益重复计算。

## 13.5 操作四：写客户内部立项材料

### 步骤

1. 按客户模板写，不用厂商模板；
2. 结构对齐客户立项要求：背景、必要性、方案、投资、收益、风险；
3. 每个数字标来源或假设；
4. 写清不包含项与依赖条件；
5. 给客户对口人一版可编辑稿。

### 预期结果

客户能直接拿去内部评审，不用重写。

### 常见错误

- 写成产品介绍；
- 数字没有来源；
- 不写依赖条件，立项后推不动。

## 13.6 操作五：过客户评审

### 步骤

1. 问清评审流程：谁审、审什么、多久；
2. 提前把材料给关键评审人；
3. 准备三类问题：价值、风险、替代方案；
4. 评审会由客户主讲，BTE 补充；
5. 评审意见逐条记录，能改的改，不能改的说明。

### 预期结果

立项材料过评审，或知道卡在哪。

### 常见错误

- 厂商主讲，客户没有 ownership；
- 评审前不沟通，现场答不上；
- 评审意见不跟踪。

## 13.7 操作六：设价值验证

### 步骤

1. 把案例中的承诺值写进验证表；
2. 每个指标写取数方式、频率、责任人；
3. 上线后按月或按季取数；
4. 偏差超过 20% 写归因；
5. 验证结果进入 VBR 素材。

### 预期结果

价值可验证，续约时有证据。

### 常见错误

- 签单后不跟踪；
- 只跟踪技术指标，不跟踪业务指标；
- 偏差不归因。

## 13.8 验收标准

| 验收项 | 通过标准 | 验证方式 |
| --- | --- | --- |
| 假设完整 | 四段齐全，读得通 | 抽查假设表 |
| 基线可信 | 指标口径与来源明确 | 核对基线记录 |
| 三笔账齐 | 收益、成本、风险齐全 | 核对业务案例 |
| 客户可用 | 客户能直接提交立项 | 客户确认 |
| 评审有记录 | 意见逐条跟踪 | 核对评审记录 |
| 验证可执行 | 指标有取数方式与责任人 | 核对验证表 |

关键项是基线可信、三笔账齐、客户可用。任一未过，业务案例不算合格。

## 13.9 执行故障排查

| 症状 | 常见原因 | 处理动作 |
| --- | --- | --- |
| 客户不认 ROI | 基线不清或假设太多 | 先补基线，再减假设 |
| 立项材料退回 | 用了厂商模板 | 改用客户模板 |
| 评审卡在风险 | 风险账没写 | 补失败模式与缓解 |
| 收益越算越大 | 重复计算 | 请客户财务复核 |
| 立项后推不动 | 依赖条件没写 | 补依赖与 Owner |
| 上线后价值对不上 | 没设验证 | 补验证表与季度复盘 |

## 13.10 执行检查清单

- [ ] 价值假设四段齐全
- [ ] 基线指标有口径、来源、年份
- [ ] 收益、成本、风险三笔账齐全
- [ ] 每笔账分事实、估算、判断
- [ ] 立项材料用客户模板
- [ ] 关键数字有来源或假设
- [ ] 客户评审意见已逐条跟踪
- [ ] 价值验证表已建立

---

**本章要点回顾**

1. 客户立项靠自己的业务案例，不靠厂商 PPT。
2. 价值假设四句话：问题、能力、后果、价值。
3. 基线是账的地基，口径与来源要客户确认。
4. 三笔账：收益、成本、风险。每笔分事实、估算、判断。
5. 立项材料用客户模板，客户主讲。
6. 价值验证表签单前建，续约时用。
