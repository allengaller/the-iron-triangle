# 第 12 章　需求与场景

> 客户说的需求，常常不是该买的东西。BTE 要把“想要”还原成“场景”，再把场景变成可判断的需求。本章给六个动作：访谈三类人、还原场景、写五要素、排优先级、冻基线、交 SA。

## 12.1 前置条件与目标

| 前置条件 | 检查内容 | 缺项处理 |
| --- | --- | --- |
| 商机已立项 | 过四问与硬门槛 | 先回第 11 章 |
| 访谈对象 | 业务、技术、决策三类人 | 先约人 |
| 业务资料 | 流程、指标、系统现状 | 先要资料 |
| 需求模板 | 五要素表 | 先用 TAM 附录 C 口径 |
| SA 接口 | 技术调研分工 | 先定协作 |

完成标志有五项：场景可复述；需求有五要素；优先级清楚；基线已签认；SA 接手无歧义。

| 目标 | 完成标志 | 主要证据 |
| --- | --- | --- |
| 场景真实 | 客户认可场景还原 | 场景卡 |
| 需求完整 | 每条需求五要素齐全 | 需求表 |
| 优先级清 | 必须、应该、可以分档 | 优先级表 |
| 基线可签 | 客户签认范围与假设 | 基线确认页 |
| 交接清楚 | SA 能复述需求边界 | 交接记录 |

## 12.2 操作一：访谈三类人

### 步骤

1. 访谈业务人：问目标、损失、流程、时间窗；
2. 访谈技术人：问系统、数据、集成、约束；
3. 访谈决策人：问为什么现在做、预算、成功标准；
4. 每类至少一人，关键项目至少两人；
5. 访谈后 24 小时内发纪要，请对方确认。

### 预期结果

需求来自三类视角，不是单一接口人的转述。

### 常见错误

- 只访技术口，漏掉业务目标；
- 只访接口人，见不到决策人；
- 访谈不记录，回头各说各话。

## 12.3 操作二：还原场景

### 步骤

1. 用“谁、在什么时点、做什么、遇到什么、希望怎样”五段写场景；
2. 每个场景配一个可观察指标；
3. 让客户业务人复述场景，确认无偏差；
4. 标出场景的频率、影响、现状替代方案；
5. 场景超过五个的，先合并同类项。

### 预期结果

需求从“要一个系统”变成“某角色在某时点要完成某件事”。

### 常见错误

- 场景写成功能清单；
- 没有指标，无法验证；
- 场景太多，没有重点。

## 12.4 操作三：写需求五要素

### 步骤

1. 按 TAM 附录 C 口径写五要素：场景、量化影响、分级与竞品、替代方案、验收标准；
2. 每条需求只写一个场景；
3. 量化影响写现状、目标、差距；
4. 分级写必须、应该、可以；
5. 替代方案写客户现在怎么做、为什么不满意。

### 预期结果

每条需求可判断：值不值得做，怎么做，怎么验收。

### 常见错误

- 五要素缺项，需求无法评估；
- 量化影响写“提升效率”；
- 不写替代方案，高估需求刚性。

## 12.5 操作四：排优先级

### 步骤

1. 按业务影响、紧迫性、实现成本、风险四维打分；
2. 分三档：必须、应该、可以；
3. 必须项超过三项的，继续压缩；
4. 与客户确认优先级，不自己排；
5. 优先级变化要写原因。

### 预期结果

客户与团队对“先做什么”有共识。

### 常见错误

- 所有需求都是必须；
- 按客户嗓门排优先级；
- 排完不确认，方案做完才发现方向错。

## 12.6 操作五：冻结需求基线

### 步骤

1. 把范围、假设、不包含项写成基线；
2. 基线包含场景、五要素、优先级、验收标准；
3. 客户对口人签字，关键项目决策人签字；
4. 基线变更走书面，口头不算；
5. 基线作为方案与报价的输入。

### 预期结果

需求有版本，后续变更可追溯。

### 常见错误

- 基线只有范围，没有假设；
- 不写不包含项，交付期扯皮；
- 变更不记录，范围越做越大。

## 12.7 操作六：交给 SA

### 步骤

1. 把场景、五要素、优先级、基线交给 SA；
2. 开一次交接会，SA 复述需求边界；
3. 标出技术不确定点，由 SA 评估；
4. 标出商业约束：预算、时间、合规、竞争；
5. 约定后续变更接口。

### 预期结果

SA 拿到的是可设计的输入，不是一叠客户原话。

### 常见错误

- 只转文档，不开交接会；
- 技术不确定点不标，SA 重复调研；
- 商业约束不传，方案脱离预算。

## 12.8 验收标准

| 验收项 | 通过标准 | 验证方式 |
| --- | --- | --- |
| 三类访谈 | 业务、技术、决策均覆盖 | 抽查纪要 |
| 场景可复述 | 客户确认场景卡 | 核对确认记录 |
| 五要素齐全 | 每条需求五要素完整 | 抽查需求表 |
| 优先级明确 | 必须、应该、可以分档 | 核对优先级表 |
| 基线签认 | 范围、假设、不包含项签字 | 核对基线页 |
| 交接清楚 | SA 能复述边界 | 核对交接记录 |

关键项是五要素齐全、基线签认、交接清楚。任一未过，需求调研不算合格。

## 12.9 执行故障排查

| 症状 | 常见原因 | 处理动作 |
| --- | --- | --- |
| 需求越聊越多 | 没有优先级 | 先分必须、应该、可以 |
| 方案做完客户不认 | 场景没确认 | 回访业务人复述场景 |
| 报价反复变 | 基线没冻结 | 补基线并签认 |
| SA 重复调研 | 交接不清 | 开交接会，SA 复述 |
| 交付期扯皮 | 不包含项没写 | 补基线的不包含项 |
| 需求全是功能 | 没问业务后果 | 用五段场景重问 |

## 12.10 执行检查清单

- [ ] 业务、技术、决策三类人都访谈过
- [ ] 每个场景有五段与可观察指标
- [ ] 每条需求五要素齐全
- [ ] 优先级分必须、应该、可以
- [ ] 基线含范围、假设、不包含项
- [ ] 客户已签认基线
- [ ] SA 已复述需求边界
- [ ] 变更接口已约定

---

**本章要点回顾**

1. 需求不是功能清单。先把“想要”还原成场景。
2. 访谈三类人：业务、技术、决策。缺一类，需求就偏。
3. 需求五要素：场景、量化影响、分级与竞品、替代方案、验收标准。
4. 优先级分三档，必须项要压缩。
5. 基线要含范围、假设、不包含项，客户签认。
6. 交 SA 要开交接会，让 SA 复述边界。
