# 第 15 章　POC 与证明

> POC 不是免费试用，也不是技术表演。POC 是一次有明确业务目标、成功标准与退出条件的证明。本章给六个动作：定目标、定标准、定退出、管参与、管结论、转商机。

## 15.1 前置条件与目标

| 前置条件 | 检查内容 | 缺项处理 |
| --- | --- | --- |
| 商机已立项 | 过机会判断与硬门槛 | 先回第 5 章 |
| 业务目标 | POC 要支持什么客户决定 | 先问清 |
| 技术方案 | 证明对象与边界 | 先与 SA 对齐 |
| 客户资源 | 数据、环境、接口人 | 先确认 |
| 预算 | POC 成本谁承担 | 先谈清 |

完成标志有五项：业务目标唯一；标准可测；退出条件明确；客户参与有记录；结论可签。

| 目标 | 完成标志 | 主要证据 |
| --- | --- | --- |
| 目标唯一 | 一句话说清证明什么 | POC 计划 |
| 标准量化 | 每条标准有阈值与取数 | 成功标准表 |
| 退出明确 | 命中即停 | 退出条件页 |
| 客户参与 | 客户有 Owner 与投入 | 参与记录 |
| 结论可签 | 通过、带条件、不通过 | 结论签认页 |

## 15.2 操作一：定业务目标

### 步骤

1. 问客户：POC 通过后，你要做什么决定；
2. 把决定写成一句话：是否采购、是否扩容、是否进入下一轮；
3. 目标只写一个，不写“顺便验证五点”；
4. 目标与客户业务指标挂钩；
5. 客户对口人确认这句话。

### 预期结果

POC 有明确的商业目的，不是技术试验。

### 常见错误

- 为做 POC 而做 POC；
- 目标写成“验证产品能力”；
- 客户没想好通过后做什么。

## 15.3 操作二：定成功标准

### 步骤

1. 每条标准写指标、阈值、取数方式、时间窗；
2. 标准分通过、带条件、不通过三档；
3. 标准与业务目标直接相关；
4. 客户与厂商双方签字；
5. 标准事后不改，除非双方书面同意。

### 预期结果

POC 开始前，双方知道什么算成。

### 常见错误

- 标准事后解释；
- 标准与业务目标无关；
- 只有厂商签字，客户不认。

## 15.4 操作三：定退出条件

### 步骤

1. 写清什么情况下停止 POC；
2. 至少覆盖：环境两周不就绪、数据合规未解、关键接口人不投入、成本超预算；
3. 退出条件命中即停，不继续烧资源；
4. 退出后写复盘，不写“再试试”；
5. 退出条件双方确认。

### 预期结果

POC 有止损线，不变成无底洞。

### 常见错误

- 没有退出条件；
- 命中条件还继续；
- 退出不记录，下次重复踩坑。

## 15.5 操作四：管客户参与

### 步骤

1. 客户侧定三个角色：业务 Owner、技术接口、决策人；
2. 每个角色写投入时间与职责；
3. 周会或日会按 POC 周期定；
4. 客户不投入的，暂停或升级；
5. 参与记录进 POC 档案。

### 预期结果

POC 是客户的项目，不是厂商的独角戏。

### 常见错误

- 客户只出环境，不出人；
- 决策人从不出现；
- 客户接口人换人，POC 断档。

## 15.6 操作五：管结论

### 步骤

1. 按事前标准出结论：通过、带条件、不通过；
2. 带条件写清条件、Owner、期限；
3. 结论双方签字，不口头默认；
4. 不达标也如实写，不美化；
5. 结论进入承诺清单与方案基线。

### 预期结果

结论可信，后续交付有依据。

### 常见错误

- 不达标也说达标；
- 结论没有客户签字；
- 结论与承诺清单不一致。

## 15.7 操作六：转商机

### 步骤

1. POC 通过后，明确下一步：报价、招标、合同、扩容；
2. 把 POC 结论写进商机卡；
3. 更新机会评分与资源档位；
4. 把技术证据移交 SA 与交付；
5. 约定客户内部推进动作与时间。

### 预期结果

POC 不是终点，是商机推进的跳板。

### 常见错误

- POC 做完没有下一步；
- 结论不更新商机；
- 客户内部没人推进。

## 15.8 验收标准

| 验收项 | 通过标准 | 验证方式 |
| --- | --- | --- |
| 目标唯一 | 一句话，与客户决定挂钩 | 核对 POC 计划 |
| 标准量化 | 每条有阈值与取数 | 核对标准表 |
| 退出明确 | 命中即停条件写清 | 核对退出页 |
| 客户参与 | 三个角色有投入记录 | 核对参与记录 |
| 结论签认 | 三选一，双方签字 | 核对结论页 |
| 转商机 | 下一步与 Owner 明确 | 核对商机卡 |

关键项是标准量化、结论签认、转商机。任一未过，POC 不算合格。

## 15.9 执行故障排查

| 症状 | 常见原因 | 处理动作 |
| --- | --- | --- |
| POC 做完客户不买 | 业务目标不清 | 先问通过后做什么决定 |
| 标准吵不清 | 事前没量化 | 停下来先定标准 |
| POC 无底洞 | 没有退出条件 | 命中条件即停 |
| 客户不投入 | 没定角色与时间 | 补客户 Owner 与周会 |
| 客户质疑结论 | 记录不全 | 补原始数据与测试记录 |
| POC 后断档 | 没转商机 | 补下一步与客户推进动作 |

## 15.10 执行检查清单

- [ ] POC 业务目标一句话
- [ ] 成功标准有指标、阈值、取数方式
- [ ] 退出条件写清，双方确认
- [ ] 客户三个角色有投入记录
- [ ] 结论三选一，双方签字
- [ ] 结论进入承诺清单
- [ ] 商机卡已更新
- [ ] 下一步与 Owner 明确

---

**本章要点回顾**

1. POC 不是免费试用，是有目标的证明。
2. 先问客户：POC 通过后，你要做什么决定。
3. 成功标准事前量化，分通过、带条件、不通过。
4. 退出条件命中即停，防止无底洞。
5. 客户要有业务 Owner、技术接口、决策人。
6. 结论如实写，签认后进承诺清单，并转商机。
