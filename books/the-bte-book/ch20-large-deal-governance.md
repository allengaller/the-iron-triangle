# 第 20 章　大单治理

> 大单不是“金额大的单”，是“一个人搞不定的单”。它有多方参与、多重审批、多个否决点。本章给六个动作：立治理、判 bid、管联合体、过准入、管风险、开治理会。

## 20.1 前置条件与目标

| 前置条件 | 检查内容 | 缺项处理 |
| --- | --- | --- |
| 商机立项 | 过机会判断与硬门槛 | 先回第 5 章 |
| 治理结构 | 主责、支持、决策人 | 先定 |
| 多方清单 | 客户、伙伴、分包、监管 | 先列全 |
| 风险登记册 | 初始风险已入册 | 先建 |
| 会议节奏 | 周会或双周会 | 先排期 |

完成标志有五项：治理结构清楚；bid 决策有依据；多方责任有边界；准入与安全有结论；风险有 Owner。

| 目标 | 完成标志 | 主要证据 |
| --- | --- | --- |
| 治理清楚 | 主责、升级、决策人明确 | 治理表 |
| Bid 有据 | 成本、机会、风险三笔账 | Bid 决策记录 |
| 多方有界 | 联合体与分包责任写清 | 合作协议 |
| 准入通过 | 资质、安全、合规有结论 | 准入记录 |
| 风险可控 | 每项风险有 Owner 与期限 | 风险登记册 |

## 20.2 操作一：立治理结构

### 步骤

1. 定主责人：谁对整单负责；
2. 定三角：BTE、SA、TAM/交付；
3. 定升级路径：什么问题找谁，多久升级；
4. 定决策会：谁参加，多久一次，决策什么；
5. 写进商机卡，团队可见。

### 预期结果

大单有人牵头，问题有升级路径。

### 常见错误

- 多人负责等于没人负责；
- 升级路径不清，问题拖大；
- 治理会只汇报，不决策。

## 20.3 操作二：做 bid/no-bid

### 步骤

1. 算三笔账：投入成本、机会成本、承诺成本；
2. 评四件事：能不能赢、赢了能不能交付、值不值得、有没有替代；
3. 列硬门槛：资质、预算、决策人、交付、合规；
4. 开 bid 决策会，三选一：投、不投、带条件投；
5. 决策记录签字，不口头。

### 预期结果

大单不靠冲动，靠算账。

### 常见错误

- 见大单就投，资源拖垮；
- 只算标书成本，不算机会成本；
- 带条件投的条件没人跟踪。

## 20.4 操作三：管联合体与分包

### 步骤

1. 列多方角色：主包、分包、伙伴、客户指定供应商；
2. 写清责任边界：谁交付什么、谁对什么负责；
3. 写清商务边界：谁报价、谁收款、谁承担风险；
4. 写清接口：技术接口、商务接口、升级接口；
5. 合作协议与客户合同对齐。

### 预期结果

多方协作有边界，不出现“都以为对方负责”。

### 常见错误

- 责任边界模糊；
- 伙伴承诺客户，主包不知道；
- 分包报价穿透，客户比价。

## 20.5 操作四：管准入与安全评审

### 步骤

1. 列准入材料：资质、财务、案例、安全、服务；
2. 列安全评审：数据、权限、供应链、审计；
3. 每项写 Owner、提交日期、评审人；
4. 缺口早补，不等到投标；
5. 评审结论进入风险登记册。

### 预期结果

准入与安全不成为最后一刻的拦路虎。

### 常见错误

- 资质临时补；
- 安全评审最后做；
- 评审缺口不跟踪。

## 20.6 操作五：管风险登记册

### 步骤

1. 列风险：技术、交付、商务、合规、伙伴、客户侧；
2. 每项写概率、影响、Owner、动作、复审日期；
3. 三缺一不入册：Owner、动作、复审日期；
4. 每周治理会过 Top 5 风险；
5. 风险关闭要验证，不口头关闭。

### 预期结果

风险看得见、有人管、能关闭。

### 常见错误

- 风险写成清单，没有 Owner；
- 只登记不跟踪；
- 风险关闭不验证。

## 20.7 操作六：开治理会

### 步骤

1. 每两周一次，60 分钟；
2. 议程固定：进度、风险、决策、资源；
3. 只看变化与请求，不逐条汇报；
4. 每个决策写 Owner 与期限；
5. 会后 24 小时发纪要。

### 预期结果

治理会是决策场，不是汇报场。

### 常见错误

- 会议变成念 PPT；
- 决策不落地；
- 纪要不发。

## 20.8 验收标准

| 验收项 | 通过标准 | 验证方式 |
| --- | --- | --- |
| 治理结构 | 主责、升级、决策人明确 | 核对治理表 |
| Bid 有据 | 三笔账与四问有记录 | 核对决策记录 |
| 多方有界 | 责任、商务、接口写清 | 核对合作协议 |
| 准入通过 | 五类材料有结论 | 核对准入记录 |
| 风险可控 | 每项有 Owner、动作、复审 | 抽查风险册 |
| 治理有效 | 每次会议有决策与 Owner | 抽查纪要 |

关键项是治理结构、bid 有据、风险可控。任一未过，大单治理不算合格。

## 20.9 执行故障排查

| 症状 | 常见原因 | 处理动作 |
| --- | --- | --- |
| 大单推不动 | 主责不清 | 先定主责与升级路径 |
| 资源拖垮 | bid 没算机会成本 | 补三笔账，重做决策 |
| 伙伴掉棒 | 责任边界模糊 | 补合作协议与接口 |
| 准入卡住 | 材料临时补 | 建准入材料台账 |
| 风险失控 | 没有 Owner | 补风险登记册三要素 |
| 治理会无效 | 只汇报不决策 | 改议程，只留决策项 |

## 20.10 执行检查清单

- [ ] 主责、三角、升级路径明确
- [ ] Bid 三笔账与四问有记录
- [ ] 多方责任、商务、接口写清
- [ ] 准入五类材料有 Owner 与日期
- [ ] 安全评审结论已入风险册
- [ ] 风险册每项有 Owner、动作、复审
- [ ] 治理会每两周一次并有决策
- [ ] 会后纪要 24 小时内发出

---

**本章要点回顾**

1. 大单是“一个人搞不定的单”，不是金额大的单。
2. 先立治理：主责、三角、升级路径、决策会。
3. Bid/no-bid 算三笔账：投入、机会、承诺。
4. 联合体与分包要写清责任、商务、接口。
5. 准入与安全评审前置，缺口早补。
6. 风险册三缺一不入册，治理会只做决策。
