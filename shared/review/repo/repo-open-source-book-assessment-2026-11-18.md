# 仓库级评估：按技术综合开源图书的最高标准（2026-11-18）

> 评估对象：the-iron-triangle 全仓（三书 200 个 md、公用层 31 个 md（不含本报告）、仓库根 2 个 md，书稿合计 91.4 万字符）。
> 评估方法：六条门禁命令与 `link_check.py` 现场复跑、磁盘全量量化、抽样通读、与成熟开源技术图书的通行做法逐项对照。
> 评估口径：本报告只评"仓库作为一本开源图书产品"的工程、治理、出版、法务与可复现性。
> 分工声明：内容深度的比对已由 `the-tam-book-overall-assessment-2026-11-10.md` 与 `sa-bte-depth-breadth-2026-11-18.md` 完成，本报告引用其结论、不重复计分，避免同一缺陷被罚两次。

---

## 一、总判

**综合得分 5.9 / 10。一句话结论：方法论写作体系已经跑通，开源图书产品化还差最后一公里。**

这个分数不是对文笔的评价。正文层面，本仓已经做到多数开源技术书没做到的事：体裁分型、口径标注、脱敏纪律、同构审计、元数据脚本化、门禁台账。这些都在跑，且有收敛证据。扣分几乎全部落在"书之外"的四件事上：仓库没有入库、许可是失效的、发布链只覆盖一本书、状态标签没有证据支撑。

| 维度 | 权重 | 得分 | 一句话依据 |
| --- | --- | --- | --- |
| 定位与读者承诺 | 10% | 8.5 | 三角分工清晰，非目标写明，反 AI 免责不回避 |
| 内容深度与结构 | 20% | 6.0 | TAM 达基准；SA 章均约为 TAM 的 1/4；BTE 居中 |
| 证据与引用链 | 15% | 5.5 | 数字有六类口径；但 SA 全书外部链接 0 条，文献不署源 |
| 可操作性资产 | 10% | 8.5 | 模板 38 件、验收表、检查清单成套，可直接搬用 |
| 质量工程 | 10% | 7.5 | 六命令 + link_check 全绿；覆盖面只到 TAM |
| 可复现与工程化 | 10% | 2.5 | 全仓未入库、无 CI、无 tag、依赖未声明 |
| 出版与分发 | 10% | 4.5 | BTE 有 HTML/EPUB/PDF；TAM 只有阅读站；SA 什么都没有 |
| 开放治理与法务 | 7% | 3.5 | LICENSE 路径失效、代码无许可、"开源"与 NC 条款冲突 |
| 跨书一致性 | 5% | 6.0 | 链接零断；但章号级口径互相打架，且无检查项 |
| 可及性与国际化 | 3% | 5.0 | 站点有 lang／alt／搜索；无摘要英文、无翻译入口、无存档 DOI |

三句话概括：

1. **它已经是一套可复用的写作操作系统，还不是一本可引用的开源图书。** 前者是团队资产，后者才对外部读者成立。
2. **最大的风险不是写得不够好，而是丢了。** git 追踪的 6,061 个文件全是旧布局，当前的 `books/` 与 `shared/` 被追踪数为 **0**，一次误操作就是全仓归零。
3. **最大的信任风险是状态标签。** SA 自称"成稿"，而它从未被内容门禁扫过一次，且自家 11-18 的评估已建议降为初稿——结论没有回流到状态页。

## 二、评估口径与基准

"最高标准"不能凭感觉。本报告把它拆成十维，每维给可核对的判据，再与三类成熟基准对照：

| 基准类型 | 代表 | 可迁移的做法 |
| --- | --- | --- |
| 多格式开源书 | Pro Git、The Rust Programming Language | 源码级构建出 HTML/EPUB/PDF；CI 每次提交跑构建与链接检查；发布带 tag |
| 大厂免费技术书 | Google SRE 系列 | 免费在线阅读 + 纸质版；图表体系；独立勘误入口；署名与版本页 |
| 中文开源架构书 | 《凤凰架构》一类 | 单仓单书、版本号与 tag 对齐、勘误走 Issue、正文与示例代码分许可 |

三类的共同点只有四条：**可溯源、可重建、可引用、可纠错。** 本报告全部判据围绕这四条展开，而不是"有没有更多章节"。

判分规则：每维 10 分，扣分必须给出可复核证据；无可核证据的项不扣分，也不加分。

## 三、逐维证据

### 3.1 定位与读者承诺：8.5

这一维接近满分，因为三书把"不做什么"写进了正文，而不只是写"做什么"。

正面证据：

- 三书分工有唯一事实源（[《承诺链》](../../00-commitment-chain.md)），接缝的归属有对照表，不靠读者自己拼。
- 状态口径四级独立成文（[《完成状态口径》](../../00-reading-status.md)），把"能不能引用"从感觉变成判据。
- AI 辅助的署名责任写在版权页（[TAM 前置页](../../../books/the-tam-book/00-front-matter.md)）：判断、结构、取舍由作者决定，起草与核查由脚本辅助，每条结论由作者负责。这句话在开源书里很少见，且立场正确。
- 自订标准 17 份统一带"（拟定稿）"与四句徽标，门禁强制。这条直接消灭了"拿草案冒充官方标准"的最大可信度风险。

扣分项：

- 仓库名改成了"三书仓库"，落地页还停在单书。`shared/gtm/index.html` 的 title 仍是《The TAM Book of AI Era》，导航全部指向 TAM，全文只出现两次"铁三角"、零次"三书"。外部读者点进来，看到的是"一本 TAM 书的营销页"，与 README 的"铁角指北"定位不一致。
- 根 README 第一句在解释更名历史，而不是告诉读者"这里能拿到什么"。

### 3.2 内容深度与结构：6.0

引用前序评估的现场数据，不重复测算：TAM 章均 4,811 字、SA 1,044 字、BTE 1,475 字；SA 33 个正文章全部不足 2,000 字，自有六维章也只有 1,000–1,700 字。

本报告补充两点前序评估未展开的结构问题：

**其一，收尾模板的覆盖率已经接近 100%。** 143 个章与附录文件中，137 个以"要点回顾"收尾（96%）。QUALITY-GATE 早就警告过这个风险——"76/82 文件以要点回顾收尾，批量改会造成新的同构"。如今比例更高。对 Explanation 章，回顾是收束；对 Reference 章（术语表、流程速查、评估标准），回顾是重复正文。建议按体裁分档：Explanation 保留，Reference 与 Tutorial 改为"常见误用"或"下一步动作"。

**其二，章内枚举被句号截断，是可复核的机械损伤。** 样例（SA 第 9 章第 15 行）：

> 完成标志有四项：每条承诺过四问、SLA 有口径。三件套已移交、偏差可回溯。

"四项"被句号切成 2+2，语义结构毁了。同类可复核样例至少 7 处：SA `ch09`／`ch10`／`ch13`／`ch16` 第 15 行、TAM `ch06-technical-depth-practical`／`ch08-business-insight-practical` 第 15 行、`appx-t-online-change-standard` 第 92/99 行。根因是"中文长句 > 25 字必须断"这条规则被机械执行到了枚举句上。断句规则缺一条例外：**顿号列举中不得插入句号。**

### 3.3 证据与引用链：5.5

数字断言的治理是这个仓库最强的一块，也是它对中文技术写作的可迁移贡献：

- 六类口径（〔标准〕〔监管〕〔厂商〕〔经验值〕〔建议值〕〔案例虚构值〕）解决了"无出处数字最难被发现"的问题。
- `claim_audit.py` 首跑 102 个无口径块，逐轮修到 0，且留下块数收敛曲线（102→52→39→36→22→19→8→4→0）。这是可复跑的治理证据，不是声称。
- TAM 正文有 107 处口径标注、60 条外部链接。

但引用链有两处结构性缺口：

**缺口一：SA 全书外部链接 0 条，BTE 1 条。** 这不是"没写参考文献"的小问题。SA 讲金融信创、等保、POC、TCO，每一节都在用外部世界的规则，却没有一条可点的原始出处。TAM 的 60 条链接证明这套写法可行，SA/BTE 只是没做。

**缺口二：全仓零脚注。** 没有 `[^1]` 体系，只有行内链接与附录 D 的推荐书目。行内链接的失效方式是静默的——源站改版后链接还活着，内容已变。建议对时效性结论补"检索时点"，TAM 第 26 章的"事实锚点（检索时点 2026-11-17）"是正确样式，应推广为三书统一格式。

### 3.4 可操作性资产：8.5

模板 38 件（TAM 23／BTE 10／SA 5）、附录级验收表、章节级勾选清单，规模与完成度都高于同类开源书。读者能拿一个真实项目按清单走完，这是本仓"落地判据"的核心承诺，也确实做到了。

扣分只在一处：模板与章节的**回链是单向的**。模板指向章节，章节不逐条指向模板，读者在执行到某一步时想找对应表格，只能去 README 的模板表里翻。SA 尤其明显——5 件模板、33 章，平均 6.6 章才有一件工具。

### 3.5 质量工程：7.5

现场复跑结果（全部在仓库根执行）：

| 命令 | 结果 |
| --- | --- |
| `content_gate.py --strict` | 样本 71｜block 0｜warn 39｜通过 32 |
| `claim_audit.py` | 高风险断言 0｜无口径块 0｜涉及 0 文件 |
| `similarity_audit.py --report` | 同构簇 3｜文本重合超线 1 对（附录 P/Q 0.18） |
| `gen_metadata.py --check` | 元数据一致，无漂移 |
| `xref_check.py` + `xref_check2.py` | 发现问题 0 条／节号级问题 0 条 |
| `link_check.py` | 扫描 1,457 条本地链接，断链 0 条 |

这套门禁的设计水平高于多数开源书：block/warn 分层、盲区写在指标旁边、Goodhart 三条禁令、阈值变更必须重校准并留痕。warn 从 11-10 的 56 降到 39，是真实收敛。

扣分有三处，都属"能力边界"而非"执行不力"：

1. **覆盖面只到 TAM。** `content_gate.py`、`claim_audit.py` 的 `ROOT` 硬编码为 `books/the-tam-book`。SA 与 BTE 从未被扫过一次，而 SA 已被标成"成稿"。
2. **门禁只跑在人脑里。** 没有 CI，六条命令靠自觉。`--report` 不跑不会报错，台账就静默过期。
3. **只查链接存在，不查指向是否正确。** 第 3.9 节的 SA 章号串台就是这类漏网。

### 3.6 可复现与工程化：2.5

这是全书最低的一维，且它是最不该低的一维。

**P0：整仓处于未入库状态。** `git ls-files books shared` 返回 0。追踪的 6,061 个文件全部是旧布局（`the-tam-book/`、`standards/`、`gtm/` 在根），工作区里这些旧路径全部标记为删除，新布局 `books/`、`shared/`、`AGENTS.md`、`.qoder/` 全部未追踪。含义很直接：**任何人现在从 GitHub clone，拿到的是几个月前的旧结构；而当前全部成果只存在于这一台机器的工作区。** 对一个以"公开写作过程"为卖点的仓库，这是最重的一条。

**P0：没有 tag。** `git tag` 为空。BTE 已经出了 v1.0 的三格式发布包，SA 与 TAM 也有版本号，但版本号没有任何一个对应到 commit。引用页写着"v1.0 起可以正式引用"（[《如何引用》](../../00-citation.md)），而无法定位到 v1.0 对应的提交——这句话目前不可兑现。

**P1：没有 CI。** 没有 `.github/`，没有 Issue 模板，没有 PR 检查。六条门禁与 `link_check` 全部依赖操作者记得跑。

**P1：依赖未声明。** `build.sh` 依赖 pandoc 与中文字体，`make_cover.py` 依赖 Pillow 与 macOS 字体，`build_web.py` 依赖 Python 3。仓库里没有任何 `requirements.txt`、`Makefile` 或"前置依赖"清单。新贡献者第一次构建必然撞环境。

### 3.7 出版与分发：4.5

三书的出版能力是三条不同的断点：

| 书 | 在线阅读站 | HTML | EPUB | PDF | 发布包 | 索引 |
| --- | --- | --- | --- | --- | --- | --- |
| TAM | 有（99 页，含站内搜索、目录、字号） | 无 | 无 | 无 | 无 | 有（脚本生成） |
| BTE | 无 | 有 | 有 | 有 | 有（v1.0 zip） | 无 |
| SA | 无 | 无 | 无 | 无 | 无 | 无 |

旗舰书 TAM 体量最大（66.6 万字符、38 章、29 附录），反而只有网页一种形态。读者想离线读、想打印、想在 Kindle 上读，都做不到。而 BTE 只有 16.5 万字符，却独占全套产线。产线配置与书的体量、成熟度倒挂。

阅读站的工程质量值得肯定：`lang="zh-CN"`、图片 alt 全非空（18 张图零空 alt）、站内搜索、目录抽屉、字号记忆、进度条。这套体验如果推到三书，是明显的读者价值。

### 3.8 开放治理与法务：3.5

**许可文本已经失效。** 根 `LICENSE` 有三个具体问题：

1. **覆盖范围写错。** 正文写"位于 `the-tam-book/` 与仓库根部的 README、gtm/"。三书现在在 `books/`，公用层在 `shared/`。按字面读，SA、BTE 与 `shared/` 的 281,279 字符不在许可范围内。
2. **指向一个不存在的文件。** "见 `the-tam-book/manuscript/appx-e-contribution-guide.md`"——`manuscript/` 目录早已不存在（实测 `ls` 报 No such file）。
3. **标题是单书。** "# The TAM Book of AI Era" 与仓库三书定位不符。

**许可类型与"开源"冲突。** README 与落地页都自称"开源图书"，而 CC BY-NC-SA 4.0 含"非商业性使用"，按 OSI 定义不属于开源许可，按 CC 官方建议也不适用于软件。`shared/tooling/` 有 21 个 Python/Shell/JS/CSS/HTML 文件、`shared/figures/` 有 17 张 SVG，这些是代码与可执行资产，用 CC 许可发布会让企业用户无法合规使用，也让"开源"这个词站不住。两条路选一条：改称"开放获取（open access）"；或内容维持 CC BY-NC-SA、代码另采 Apache-2.0 或 MIT，在 LICENSE 里分节写清。

**贡献治理只有一个入口，且只覆盖一本书。** 贡献指南是 TAM 附录 E。SA 没有贡献指南、没有术语表、没有 CHANGELOG。仓库根没有 CONTRIBUTING、没有 CODE_OF_CONDUCT、没有 Issue 模板。外部贡献者想报一个勘误，得先读完一本 66 万字的书找到附录 E。

### 3.9 跨书一致性：6.0

机器可查的部分是全绿的：1,457 条链接零断、章号／附录字母／模板号零错、节号引用零错。这已经超过绝大多数多书仓库。

但机器查不到的地方有一处硬伤。SA 第 9 章（自称"样章"）同一个口径指向了三个不同章节：

| 位置 | 原文 | 指向 |
| --- | --- | --- |
| 章首导语与 9.3 | "口径与《The TAM Book》第 34 章同源" | TAM 第 34 章（正确） |
| 9.5 | "正式口径将立于第 25 章" | SA 第 25 章（正确） |
| 9.7 故障排查 | "先对第 26 章口径再谈" | SA 第 26 章 = 成熟度模型（错误） |
| 9.8 检查清单 | "SLA 口径引自第 26 章" | 同上（错误） |

`xref_check2` 之所以没拦住，是因为它验"节号存在"，不验"指向的章讲的是不是这件事"。这类错误的检测成本远低于修复成本：把"每章首段的跨章引用"抽成一张声明表，人工核一遍即可，不必上模型。

### 3.10 可及性与国际化：5.0

已具备：`lang` 属性、图片 alt 全覆盖、字号可调、深浅主题、搜索、移动端 viewport、Markdown 纯文本可被读屏软件顺序读取。

缺口三项：

- **无英文入口。** 三书标题都是双语的，但仓库没有一个英文摘要页。国际读者打开 README 只能看到中文。
- **无存档锚点。** 没有 DOI（Zenodo/Figshare 均可免费拿到）、没有 `CITATION.cff`。学术引用与长期存档都缺一个稳定标识。
- **归档区未做入仓决策。** `shared/well-architected/` 有 40 MB 只读副本，是否随仓库发布、是否可复跑抓取，目前没有明文约定。40 MB 对 clone 成本有实际影响。

## 四、P0：七件必须先修的事

顺序按"不做会出事"排，不按工作量排。

| # | 事项 | 具体动作 | 完成判据 |
| --- | --- | --- | --- |
| 1 | **整仓入库** | 提交 `books/`、`shared/`、`AGENTS.md`、`.qoder/`；旧布局删除与新增放在同一个提交，保证任一 commit 可 checkout 出完整结构 | `git ls-files books \| wc -l` > 200；`git status` 干净 |
| 2 | **状态标签回退** | SA 由"成稿"改"初稿"，三处同步（书 README、根 README、状态页）；理由写明"内容门禁未覆盖" | 三处一致；状态页附 11-18 评估链接 |
| 3 | **LICENSE 重写** | 三书范围改为 `books/`、`shared/`、根文档；删除 `manuscript/` 死链；代码另节 Apache-2.0；标题改三书 | 逐条可对照目录树；`grep manuscript LICENSE` 为空 |
| 4 | **打 tag** | 为 BTE v1.0 补 `bte-v1.0`（指到构建产物的源提交）；TAM v0.3 补 `tam-v0.3` | `git tag` 非空；tag 指向的 commit 能重建产物 |
| 5 | **门禁解除硬编码** | `content_gate.py`／`claim_audit.py` 增 `--book` 参数，默认全三书；先对 SA/BTE 只出 `--report` 台账，不阻断 | 三书各有一份 `content-gate-report.md` |
| 6 | **HANDOFF 拆分** | 214,915 字符、330 行、单行最长 4,083 字符——已被工具读取上限截断过一次。按"决策／踩坑／待办"拆成三文件，单文件控制在 40 KB 内 | 任一文件可一次读完；AGENTS 的入口链接同步 |

## 七、与"最高标准"的具体差距

把上面的条目压缩成一张对照表，差距就一目了然。

| 能力 | 成熟开源书做法 | 本仓现状 | 差距性质 |
| --- | --- | --- | --- |
| 版本可定位 | 每次发布打 tag，README 指向 release | 无 tag，版本号无处落地 | 缺失 |
| 构建可重建 | 一条命令产出全部格式，依赖写进文件 | BTE 有、TAM/SA 无；依赖未声明 | 部分缺失 |
| 提交即校验 | CI 跑构建与链接检查 | 六命令靠人记 | 缺失 |
| 引用可存档 | DOI + `CITATION.cff` | 只有仓库 URL | 缺失 |
| 许可分层 | 内容 CC、代码 MIT/Apache 分节 | 全仓一份 CC，范围还写错 | 错误 |
| 勘误闭环 | Issue 模板 + ERRATA 页 | 埋在附录 E | 弱 |
| 多格式 | HTML/EPUB/PDF 齐全 | 一书的格式都不齐 | 部分缺失 |
| 内容深度 | 章均 3,000–6,000 字 | TAM 达标，SA/BTE 不达标 | 部分达标 |
| 证据密度 | 关键论断逐条注源 | TAM 达标，SA/BTE 近零 | 部分达标 |
| 治理透明 | 决策与踩坑公开留痕 | HANDOFF/QUALITY-GATE 水平超基准 | **领先** |

最后一行值得单独说：**治理文档是这家仓库的护城河，不是负担。** QUALITY-GATE 里"指标一旦成为目标就不再是好指标"、"block 管能不能用、warn 管写得好不好"这些判断，比多数开源书的贡献指南更有价值。问题只在于它们被锁在一个 215 KB 的单文件里，且没有 CI 执行。

## 八、不建议做的事

评估报告的另一半价值是劝阻。

1. **不要为降 warn 数而改稿。** warn 从 56 降到 39 是真实收敛。继续追数字会重演"为过线而写"的老路。台账按"改它值不值"排序，这条原则已经写对了。
2. **不要在 SA/BTE 深度补齐前建阅读站。** 先有内容再有产线。SA 章均 1,044 字，做成漂亮的网页只会放大"薄"的观感。
3. **不要新增附录。** TAM 附录 29 个已超过正文的三分之二，同构审计刚清完一批批量填充件。新内容一律并入既有主件的"执行落地"节。
4. **不要改名 P 前缀。** 四义并存已裁定，改名波及上百处引用，收益为零。
5. **不要把 `warn` 变成 `block`。** 具象密度这类指标没有普适阈值，阻断会逼作者编数据——QUALITY-GATE 已经把这条道理写透，执行时别忘。
6. **不要给三书做"统一文风重写"。** 同构审计已经证明批量改会造成新的同构。按章改，改论证，不改措辞。

## 九、改进如何验收

改进不能靠"感觉好多了"。这份报告提出的七件事，可以用同一组命令验证：
